## 摘要

大语言模型（LLM）在生成上下文连贯的回复方面已展现出卓越能力，但其固定的上下文窗口（context window）为在长时间跨度的多会话对话中维持一致性带来了根本性挑战。我们提出 **Mem0**，一种以记忆为中心的可扩展架构，通过动态地从持续进行的对话中抽取、整合与检索显著信息来解决这一问题。在此基础上，我们进一步提出一种增强变体，利用**基于图的记忆表示**（graph-based memory representation）来捕获对话要素之间复杂的关系结构。

通过在 LOCOMO 基准上的全面评估，我们将所提方法与六类基线进行了系统性比较：(i) 已有的记忆增强系统；(ii) 采用不同分块大小（chunk size）与 $k$ 值的检索增强生成（RAG）；(iii) 处理完整对话历史的**全上下文**（full-context）方法；(iv) 一个开源记忆方案；(v) 一个商业模型系统；(vi) 一个专用的记忆管理平台。

实证结果表明，我们的方法在四类问题——单跳（single-hop）、时间（temporal）、多跳（multi-hop）与开放域（open-domain）——上一致优于所有现有记忆系统。值得注意的是，Mem0 在 LLM-as-a-Judge 指标上相对 OpenAI 取得 **26% 的相对提升**，而带图记忆的 Mem0 相比基础配置总体得分再高出约 **2%**。除准确率收益外，我们相比全上下文方法还显著降低了计算开销：Mem0 的 **p95 延迟降低 91%**，并节省 **超过 90% 的 token 成本**，从而在高级推理能力与实际部署约束之间取得了极具吸引力的平衡。

我们的发现强调了结构化、持久化的记忆机制对长期对话连贯性的关键作用，为更可靠、更高效的 LLM 驱动 AI 智能体铺平了道路。

## 1 引言

人类记忆是智能的基石——它塑造我们的身份、引导决策，并使我们能够学习、适应并建立有意义的关系（Craik and Jennings, 1992）。在其众多角色中，记忆对沟通尤为关键：我们回忆过去的互动、推断偏好，并对交往对象构建不断演化的心智模型（Assmann, 2011）。这种在长时间跨度内保持与检索信息的能力，使跨越数天、数周乃至数月的一致性、上下文丰富的交流成为可能。

由大语言模型（LLM）驱动的 AI 智能体在生成流畅、上下文恰当的回复方面已取得显著进展（Yu et al., 2024; Zhang et al., 2024）。然而，这些系统从根本上受限于对固定上下文窗口的依赖，这严重制约了它们在长时间交互中维持连贯性的能力（Bulatov et al., 2022; Liu et al., 2023）。

这一局限源于 LLM 缺乏能够超越其有限上下文窗口的**持久记忆机制**。人类会自然地随时间累积并组织经验、形成连续的交互叙事，而 AI 系统无法天生地在不同会话之间、或在上下文溢出之后持久保存信息。

持久记忆的缺失在人机交互中造成根本性的断裂。没有记忆，AI 智能体会忘记用户偏好、重复提问，并与先前确立的事实相矛盾。考虑图 1 所示的一个简单例子：用户在最初一次对话中提到自己是素食者、不吃乳制品。在后续会话中，当用户询问晚餐推荐时，没有持久记忆的系统可能会推荐鸡肉，完全违背了已确立的饮食偏好。相反，具备持久记忆的系统会跨会话保留这一关键用户信息，并给出合适的素食、无乳制品选项。这一常见场景说明记忆失效如何从根本上损害用户体验与信任。

> **图 1 | AI 智能体中记忆重要性的图示。** 左：没有持久记忆时，系统在会话之间遗忘了关键用户信息（素食、无乳制品偏好），导致给出不恰当的推荐。右：具备有效记忆时，系统在各次交互中保留这些饮食偏好，从而能够给出与先前确立的约束相符的、上下文恰当的建议。
>
> *（译者注）* 图左的对话大致为：会话 1 用户说"我是素食者，也不吃乳制品"；会话 2 用户问"晚餐吃什么好？"，系统回答"烤鸡配酸奶酱如何"——典型的偏好遗忘导致的矛盾推荐。图右的同一场景下，系统回答类似"香煎豆腐配藜麦沙拉（全素、无乳制品）"，并援引了会话 1 的偏好。

除对话场景之外，记忆机制也被证明能在交互式环境中大幅提升智能体表现（Majumder et al.; Shinn et al., 2023）。配备过往经验记忆的智能体能更好地预判用户需求、从先前错误中学习，并把知识泛化到不同任务（Chhikara et al., 2023）。研究表明，记忆增强的智能体通过利用动作与结果之间的因果关系改进决策，从而在动态场景中实现更有效的适应（Rasmussen et al., 2025）。分层记忆架构（Packer et al., 2023; Sarthi et al., 2024）与具备自主演化能力的智能体记忆系统（Xu et al., 2025）进一步表明，记忆使跨多个对话会话的、更连贯的长期推理成为可能。

与人类能够动态整合新信息并修正过时信念不同，LLM 一旦信息落到上下文窗口之外，实际上就被"重置"了（Zhang, 2024; Timoneda and Vera, 2025）。即便 OpenAI 的 GPT-4（128K tokens）（Hurst et al., 2024）、o1（200K 上下文）（Jaech et al., 2024）、Anthropic 的 Claude 3.7 Sonnet（200K tokens）（Anthropic, 2025）以及 Google 的 Gemini（至少 10M tokens）（Team et al., 2024）不断刷新上下文长度边界，这些改进也只是**推迟**而非**解决**这一根本局限。

在实际应用中，即便是这些扩展后的上下文窗口也被证明不够用，原因有两个关键方面。第一，随着有意义的人机关系在数周或数月内发展，对话历史不可避免地会超出即便是最宽裕的上下文限制。第二，或许更重要的是，真实世界的对话很少保持主题连续性。用户可能先提到饮食偏好（是素食者），接着花数小时讨论编程任务等无关话题，然后又回到关于晚餐选择的饮食类问题。在这类场景下，全上下文方法必须穿过堆积如山的无关信息进行推理，而关键的饮食偏好可能被埋在数千个 token 的编程讨论之中。此外，仅仅提供更长的上下文并不能保证对过往信息的有效检索与利用，因为注意力机制在远距离 token 上会退化（Guo et al., 2024; Nelson et al., 2024）。

这一局限在医疗、教育与企业支持等高风险领域尤为突出，这些领域中维持连续性与信任至关重要（Hatalis et al., 2023）。为应对这些挑战，AI 智能体必须采用超越静态上下文扩展的记忆系统。一个稳健的 AI 记忆应当有选择地存储重要信息、整合相关概念，并在需要时检索相关细节——这与人类认知过程相仿（He et al., 2024）。通过整合此类机制，我们可以构建出能够维持一致人设、跟踪演化的用户偏好、并在先前交流基础上持续累积的 AI 智能体。这一转变将把 AI 从短暂、健忘的应答者，转变为可靠的长期协作者，从根本上重新定义对话智能的未来。

在本文中，我们针对 AI 系统的一项根本局限：无法在跨会话的长时间对话中维持连贯推理，而这严重制约了与用户进行有意义的长期交互。我们提出 **Mem0**（读作 "mem-zero"），一种新颖的记忆架构，能够动态地从持续进行的对话中捕获、组织与检索显著信息。在此基础之上，我们开发了 $\text{Mem0}^{g}$，用基于图的记忆表示增强了基础架构，以更好地建模对话要素之间的复杂关系。

我们在 LOCOMO 基准上的实验结果表明，我们的方法在多种问题类型上一致优于现有记忆系统——包括记忆增强架构、检索增强生成（RAG）方法，以及开源与商业方案——同时所需的计算资源显著更低。延迟测量进一步显示，Mem0 的响应时间比全上下文方法低 91%，在复杂推理能力与实际部署约束之间取得了最优平衡。这些贡献代表着向"能够在长时间跨度上维持连贯、上下文感知对话"的 AI 系统迈出了有意义的一步——这些系统映照人类沟通模式，并为个人辅导、医疗与个性化助手等应用开辟了新的可能。

## 2 提出的方法

我们为 AI 智能体引入两种记忆架构。

**(1) Mem0** 实现了一种新颖范式：通过专门的记忆抽取与更新模块，从对话中抽取、评估并管理显著信息。系统处理一对消息——这对消息可以来自两个用户参与者，也可以来自用户与助手。

**(2) $\text{Mem0}^{g}$** 在此基础之上引入基于图的记忆表示：记忆被存储为**有向标记图**（directed labeled graph），实体为节点、关系为边。这种结构使系统能够更深入地理解实体之间的连接。通过显式建模实体及其关系，$\text{Mem0}^{g}$ 支持跨相互关联事实的更高级推理，尤其适用于需要在多条记忆之间沿复杂关系路径导航的查询。

### 2.1 Mem0

我们的架构遵循**增量式处理范式**（incremental processing paradigm），使其能够在进行中的对话里无缝运作。如图 2 所示，完整的流水线架构由两个阶段组成：**抽取**（extraction）与**更新**（update）。

> **图 2 | Mem0 系统架构总览，展示抽取阶段与更新阶段。** 抽取阶段处理消息与历史上下文以生成新记忆。更新阶段把抽取出的记忆与相似的既有记忆进行比对，通过 **Tool Call**（工具调用）机制施加相应操作。数据库作为中心化存储库，为处理过程提供上下文并存储更新后的记忆。
>
> *（译者注）* 上图的数据流可概括为：`(m_{t-1}, m_t)` 新消息对 + 数据库中的会话摘要 $S$ + 最近若干条消息 → LLM 抽取器 $\phi$ 产出候选事实集合 $\Omega$ → 对每个事实在向量库中检索 top-$s$ 相似记忆 → LLM 通过函数调用在 {ADD, UPDATE, DELETE, NOOP} 中选择操作 → 写回数据库。

抽取阶段在收到一对新消息 $(m_{t-1}, m_{t})$ 时启动，其中 $m_{t}$ 表示当前消息、$m_{t-1}$ 表示前一条消息。这对消息通常由一条用户消息与一条助手回复构成，捕获一个完整的交互单元。为了给记忆抽取建立恰当的上下文，系统采用两个互补的来源：

1. 从数据库中检索得到的**对话摘要** $S$，它浓缩了整个对话历史的语义内容；
2. 对话历史中最近的**消息序列** $\{m_{t-m}, m_{t-m+1}, \ldots, m_{t-2}\}$，其中 $m$ 是控制近期窗口大小的超参数。

为支持上下文感知的记忆抽取，我们实现了一个**异步摘要生成模块**，周期性刷新对话摘要。该组件独立于主处理流水线运行，确保记忆抽取始终受益于最新的上下文信息，同时不引入处理延迟。$S$ 提供贯穿整个对话的全局主题理解，而最近消息序列提供细粒度的时间上下文，其中可能包含尚未被摘要整合的相关细节。

这两路上下文信息与新消息对组合起来，构成一个完整的提示 $P=(S, \{m_{t-m}, \ldots, m_{t-2}\}, m_{t-1}, m_{t})$，输入给由 LLM 实现的抽取函数 $\phi$。该函数 $\phi(P)$ 专门从新的交流中抽取出一组显著记忆 $\Omega=\{\omega_{1}, \omega_{2}, \ldots, \omega_{n}\}$，同时保持对对话更广泛上下文的感知，产出可被纳入知识库的候选事实。

抽取之后，更新阶段会把每个候选事实与既有记忆进行比对，以维持一致性并避免冗余。该阶段为每个抽取出的事实 $\omega_{i} \in \Omega$ 确定恰当的记忆管理操作。附录 B 中的算法 1 展示了这一过程。对每个事实，系统首先使用向量嵌入从数据库中检索语义最相似的 top-$s$ 条记忆。随后，这些被检索到的记忆连同候选事实一起，通过我们称为"工具调用"（tool call）的函数调用接口提交给 LLM。由 LLM 自身决定执行以下四种不同操作中的哪一种：

| 操作 | 触发条件 | 语义 |
| --- | --- | --- |
| **ADD** | 不存在语义等价的记忆 | 创建新记忆 |
| **UPDATE** | 已有记忆可被补充信息增强 | 用互补信息扩充既有记忆 |
| **DELETE** | 新信息与既有记忆矛盾 | 删除被新信息推翻的记忆 |
| **NOOP** | 候选事实无需改动知识库 | 不做任何操作 |

我们没有使用单独的分类器，而是利用 LLM 的推理能力，基于候选事实与既有记忆之间的语义关系直接选择恰当操作。在完成该判定之后，系统执行相应操作，从而维持知识库的连贯性与时间一致性。

在我们的实验评估中，系统配置为 $m = 10$ 条历史消息作为上下文参考，$s = 10$ 条相似记忆用于对比分析。所有语言模型操作均使用 **GPT-4o-mini** 作为推理引擎。向量数据库采用稠密嵌入（dense embedding），以支持更新阶段的高效相似度搜索。

### 2.2 Mem0^g

$\text{Mem0}^{g}$ 流水线（如图 3 所示）实现了一种基于图的记忆方法，能够有效地从自然语言交互中捕获、存储与检索上下文信息（Zhang et al., 2022）。在该框架中，记忆被表示为有向标记图 $G=(V, E, L)$，其中：

- **节点** $V$ 表示实体（例如 Alice、San_Francisco）
- **边** $E$ 表示实体之间的关系（例如 lives_in）
- **标签** $L$ 为节点赋予语义类型（例如 Alice - Person、San_Francisco - City）

每个实体节点 $v \in V$ 包含三个组成部分：(1) **实体类型分类**，对实体进行归类（例如 Person、Location、Event）；(2) **嵌入向量** $e_{v}$，捕获实体的语义含义；(3) **元数据**，包括创建时间戳 $t_{v}$。系统中的关系被组织为三元组形式 $(v_{s}, r, v_{d})$，其中 $v_{s}$ 与 $v_{d}$ 分别是源实体节点和目的实体节点，$r$ 是连接二者的标记边。

> **图 3 | $\text{Mem0}^{g}$ 的图记忆架构，展示实体抽取与更新阶段。** 抽取阶段使用 LLM 把对话消息转换为实体与关系三元组。更新阶段在把新信息整合进既有知识图谱时，采用冲突检测与消解机制。
>
> *（译者注）* 抽取阶段是两段式：实体抽取器先识别实体及其类型 → 关系生成器再为实体对生成带标签的关系三元组。更新阶段：为新三元组的源/目的实体计算嵌入，在图中检索相似度超过阈值 $t$ 的既有节点（据节点是否存在，可能新建两个节点、只新建一个节点，或全部复用既有节点），然后做冲突检测，由 LLM 判定哪些旧关系应被置为失效（标记 invalid 而非物理删除，以保留时间推理能力）。

抽取过程采用两段式流水线，借助 LLM 把非结构化文本转换为结构化的图表示。首先，**实体抽取器**（entity extractor）模块处理输入文本，识别出一组实体及其对应类型。在我们的框架中，实体代表对话中的关键信息要素——包括人物、地点、物体、概念、事件以及在记忆图中值得表示的属性。实体抽取器通过分析对话要素的语义重要性、唯一性与持久性来识别这些多样化的信息单元。例如，在一段关于旅行计划的对话中，实体可能包括目的地（城市、国家）、交通方式、日期、活动以及参与者偏好——本质上就是任何可能对后续引用或推理有用的离散信息。

接下来，**关系生成器**（relationship generator）组件在这些实体之间推导有意义的连接，建立一组关系三元组，以捕获信息的语义结构。该基于 LLM 的模块分析抽取出的实体及其在对话中的上下文，以识别语义上显著的连接。它通过考察语言模式、上下文线索与领域知识来判断实体之间如何关联。对于每一对潜在实体，生成器评估是否存在有意义的关系；若存在，则用恰当的标签对该关系分类（例如 'lives_in'、'prefers'、'owns'、'happened_on'）。该模块采用提示工程技术，引导 LLM 对对话中的显式陈述与隐式信息同时进行推理，产出构成记忆图边的关系三元组，从而支持跨相互关联信息的复杂推理。

在整合新信息时，$\text{Mem0}^{g}$ 采用精细的存储与更新策略。对每个新的关系三元组，我们为源实体与目的实体都计算嵌入，然后搜索语义相似度高于既定阈值 $t$ 的既有节点。根据节点是否存在，系统可能同时创建两个节点、只创建一个节点，或直接使用既有节点，然后再以恰当的元数据建立关系。为维持知识图谱的一致性，我们实现了一个**冲突检测机制**，在新信息到来时识别可能冲突的既有关系。由基于 LLM 的**更新消解器**（update resolver）判定某些关系是否应当作废——把它们标记为失效，而不是物理删除，以便保留时间推理能力。

> *（译者注）* "标记失效而非删除"这一点在时间类问题上很关键：用户去年住在北京、今年搬到上海，两条 `lives_in` 边都会被保留，但北京那条被标为 invalid，系统因此可以回答"我去年住哪"。

$\text{Mem0}^{g}$ 中的记忆检索功能实现了**双路策略**（dual-approach）以获取最优的信息访问。**以实体为中心**的方法首先识别查询中的关键实体，然后借助语义相似度定位知识图谱中的对应节点。它系统性地探索这些锚点节点的入边与出边关系，构建一个捕获相关上下文信息的综合子图。与之互补，**语义三元组**方法采取更整体化的视角，把整个查询编码为稠密嵌入向量。该查询表示随后与知识图谱中每个关系三元组的文本编码进行匹配。系统计算查询与所有可用三元组之间的细粒度相似度分数，只返回超过可配置相关性阈值的三元组，并按相似度降序排列。这种双路检索机制使 $\text{Mem0}^{g}$ 能够同等有效地处理聚焦具体实体的定向问题与范围更宽的概念性问题。

从实现角度看，系统使用 **Neo4j**（https://neo4j.com/）作为底层图数据库。基于 LLM 的抽取器与更新模块利用具备函数调用能力的 GPT-4o-mini，从而支持从非结构化文本中进行结构化信息抽取。通过把基于图的表示与语义嵌入、基于 LLM 的信息抽取相结合，$\text{Mem0}^{g}$ 同时获得了复杂推理所需的结构丰富性与自然语言理解所需的语义灵活性。

## 3 实验设置

### 3.1 数据集

**LOCOMO**（Maharana et al., 2024）数据集专为评估对话系统中的长期会话记忆而设计。它包含 10 段超长对话，每段平均约含 600 轮对话、平均 26000 个 token，分布跨越多个会话。每段对话记录两个人讨论日常经历或过往事件。在这些多会话对话之后，每段对话还附有平均 200 个问题及对应的标准答案（ground truth）。这些问题被划分为多种类型：单跳、多跳、时间与开放域。该数据集原本还包含一个**对抗性**（adversarial）问题类别，用于测试系统识别不可回答问题（unanswerable question）的能力。然而，由于该类别的标准答案不可得，且此类问题的预期行为就是智能体应将其识别为不可回答，我们在评估中排除了这一类别。

### 3.2 评估指标

我们的评估框架采用综合方法来考察对话系统中的长期记忆能力，同时兼顾回复质量与运行效率。我们把指标分为两组，合起来提供对系统性能的整体理解。

#### (1) 性能指标（Performance Metrics）

此前对话式 AI 研究（Goswami, 2025; Soni et al., 2024; Singh et al., 2020）主要依赖词汇相似度指标，如 F1 分数（F1）与 BLEU-1（B1）。然而，这些指标在评估对话语境中的事实准确性时存在显著局限。设想一个场景：标准答案是 "Alice 出生于三月"，而系统生成的是 "Alice 出生于七月"。尽管在出生月份上包含关键事实错误，传统指标会因为其余 token（"Alice"、"born" 等）的词汇重叠而给出相当高的分数。这一根本局限会导致误导性的评估，无法捕获语义正确性。

为弥补这些缺陷，我们采用 **LLM-as-a-Judge（J）** 作为互补的评估指标。该方法利用另一个能力更强的 LLM，在多维度上评估回复质量，包括事实准确性、相关性、完整性与上下文恰当性。评判模型（judge model）分析问题、标准答案与生成答案，给出与人类判断更一致、更细致的评价。由于 J 评估具有随机性，我们对每种方法在整个数据集上独立运行 10 次，并报告平均分及 $\pm 1$ 个标准差。关于 J 的更多细节见附录 A。

#### (2) 部署指标（Deployment Metrics）

除回复质量之外，实际部署考量对于长期记忆在 AI 智能体中的真实应用至关重要。我们系统性追踪**Token 消耗**（Token Consumption），使用 tiktoken 的 'cl100k_base' 编码，统计检索阶段产出的、作为回答查询上下文的 token 数量。对于基于记忆的模型，这些 token 代表从知识库中检索到的记忆；对于基于 RAG 的模型，它们对应被检索文本分块中的 token 总数。这一区分很重要，因为它直接影响运营成本与系统效率——究竟是处理简洁的记忆事实，还是处理更大的原始文本片段。我们进一步监测**延迟**（Latency），包括：(i) **检索延迟**：检索记忆（基于记忆的方案）或分块（基于 RAG 的方案）所需的总时间；(ii) **总延迟**：生成恰当回复的时间，由检索时间（访问记忆或分块）与使用 LLM 生成答案的时间共同构成。

这些指标之间的关系揭示了系统设计中重要的权衡。例如，更精细的记忆架构可能获得更高的事实准确性，但代价是 token 消耗与延迟增加。我们的多维评估方法使研究者与从业者能够根据自身具体需求作出明智决策——无论是为关键应用优先考虑回复质量，还是为实时部署场景优先考虑计算效率。

### 3.3 基线

为全面评估我们的方法，我们与六类不同基线进行比较，它们代表了对话记忆系统的当前水平。这些多样化的基线共同构成了一个稳健的框架，用于在多个维度上评估不同记忆架构的有效性，包括事实准确性、计算效率以及对超长对话的可扩展性。在适用情况下，除非另有说明，我们把温度（temperature）设为 0，以确保运行尽可能可复现。

**已有的 LOCOMO 基准方法**

我们首先通过评估此前已在 LOCOMO 数据集上完成基准测试的方法，建立比较基础。这些包括五种既有方法：LoCoMo（Maharana et al., 2024）、ReadAgent（Lee et al., 2024）、MemoryBank（Zhong et al., 2024）、MemGPT（Packer et al., 2023）与 A-Mem（Xu et al., 2025）。这些既有基准不仅提供了与已发表结果的直接比较点，也代表了对话记忆架构在不同算法范式下的演进脉络。在评估中，我们选取使用 gpt-4o-mini 进行评估的那些指标。关于这些基准的更多细节见附录 C。

**开源记忆方案**

第二类基线由一些有潜力的开源记忆架构构成，例如 **LangMem**（https://langchain-ai.github.io/langmem/，Hot Path 模式）——它们已在相关对话任务中展现出有效性，但尚未在 LOCOMO 数据集上被评估。通过把这些系统适配到我们的评估框架，我们拓宽了比较视野，并识别出可能具备竞争力的替代方案。我们用 gpt-4o-mini 初始化 LLM，并使用 text-embedding-small-3 作为嵌入模型。

**检索增强生成（RAG）**

作为基线，我们把整段对话历史视为一个文档集合，应用标准 RAG 流水线。我们首先把每段对话切分为固定长度的分块（128、256、512、1024、2048、4096 与 8192 tokens），其中 8192 是我们的嵌入模型支持的最大分块大小。所有分块均使用 OpenAI 的 text-embedding-small-3 嵌入，以确保不同配置之间向量质量一致。查询时，我们按语义相似度检索 top-$k$ 个分块，把它们拼接作为生成答案的上下文。在整个实验中我们设定 $k \in \{1,2\}$：$k=1$ 时只使用最相关的单个分块，$k=2$ 时把最相关的两个分块（最多 16384 tokens）拼接起来。我们避免 $k>2$，因为平均对话长度（26000 tokens）会被完全覆盖，从而使选择性检索的收益消失。通过变化分块大小与 $k$，我们系统性地评估 RAG 在长期会话记忆任务上的表现。

**全上下文处理（Full-Context Processing）**

我们采用一种直接的方法：把整段对话历史放入 LLM 的上下文窗口。该方法利用模型固有的顺序信息处理能力，无需额外的架构组件。虽然概念上简单，但随着对话变长，这一方法面临实际限制，最终会抬高 token 成本与延迟。尽管如此，它仍为理解"更精细的记忆机制相对于直接处理可用上下文的价值"提供了一个重要的参照点。

**商业模型（Proprietary Models）**

我们评估 OpenAI 在其 ChatGPT 界面中提供的**记忆（memory）**功能（https://openai.com/index/memory-and-new-controls-for-chatgpt/），并特别使用 gpt-4o-mini 以保持一致。我们用一段提示词（见附录 A）把完整的 LOCOMO 对话灌入单个聊天会话，促使模型以时间戳、参与者姓名与对话文本生成记忆。随后，这些生成的记忆被用作回答该段对话相关问题的完整上下文——我们有意让 OpenAI 方案**特权性地**访问所有记忆，而不只是与问题相关的记忆。这一方法设计是为了适配 OpenAI 系统为基准测试目的而不提供选择性记忆检索外部 API 的现状。

**记忆服务提供商（Memory Providers）**

我们纳入 **Zep**（Rasmussen et al., 2025），一个为 AI 智能体设计的记忆管理平台。使用其平台版本，我们在 LOCOMO 数据集上开展系统性评估，并在保留对话内容的同时保留时间戳信息，以维持时间保真度（temporal fidelity）。这种时间锚定为时间敏感类查询提供了恰当的上下文记忆检索，对评估需要时序感知的问题尤为重要。该基线代表了一个专门为 AI 智能体打造的重要商业级记忆管理实现。

**单跳问题的表现**

单跳查询需要在一个对话轮次内定位单一事实片段。Mem0 凭借其以自然语言文本承载的稠密记忆，取得最强结果：F1 = 38.72、B1 = 27.13、J = 67.13。用图记忆来增强自然语言记忆（$\text{Mem0}^{g}$）相比 Mem0 出现轻微性能下降，说明当检索目标只占据单个轮次时，关系结构带来的效用有限。在既有基线中，全上下文的 OpenAI 运行取得次优的 J 分数，反映出把整段对话保留在上下文中的好处；而 LangMem 与 Zep 在 J 分数上均比我们的模型低约 8%（相对值）。此前的 LOCOMO 基准方法如 A-Mem 在 J 上落后 25 个点以上，凸显出即便对简单检索任务，细粒度的结构化记忆索引也是必要的。

**多跳问题的表现**

多跳查询要求综合分散在多个对话会话中的信息，在记忆整合与检索上带来显著挑战。Mem0 以 F1 = 28.64、J = 51.15 明显优于其他方法，反映出其高效检索并整合跨会话分散信息的能力。有趣的是，$\text{Mem0}^{g}$ 中增加的图记忆在此并未带来性能增益，说明在复杂整合类任务上，结构化图表示相比纯稠密自然语言记忆可能存在低效或冗余。LangMem 等基线表现有一定竞争力，但其分数明显落后于 Mem0，强调了我们在复杂查询处理上精细化的记忆索引与检索机制的优势。

**开放域的表现**

在开放域设定下，基线 Zep 取得最高的 F1（49.56）与 J（76.60），以微弱优势领先我们的方法。具体而言，Zep 的 J 分数 76.60 仅比 $\text{Mem0}^{g}$ 的 75.71 高 0.89 个百分点，比 Mem0 的 72.93 高 3.67 个百分点，凸显出其在"把对话记忆与外部知识整合"方面一致但轻微的领先。$\text{Mem0}^{g}$ 仍是强劲的次优者，J = 75.71 反映其事实检索精度高；Mem0 以 72.93 紧随其后，展现出稳健的连贯性。这些结果表明，尽管结构化关系记忆（如 Mem0 与 $\text{Mem0}^{g}$）显著改善了开放域检索，Zep 仍保持着小幅但有意义的领先。

**时间推理的表现**

时间推理任务取决于对对话历史中事件序列、其相对顺序与持续时长的准确建模。我们的架构在所有指标上都体现出显著提升，其中 $\text{Mem0}^{g}$ 取得最高的 F1（51.55）与 J（58.13），说明在自然语言记忆之外增加结构化关系表示，对时间落地的判断有显著帮助。值得注意的是，基础变体 Mem0 也给出了不错的 J 分数（55.51），说明仅凭自然语言也能辅助时间落地的判断。在基线中，OpenAI 表现明显偏弱，分数低于 15%，主要原因在于：尽管在 OpenAI ChatGPT 中显式提示要带时间戳抽取记忆，但生成的大多数记忆仍缺失时间戳。其他基线如 A-Mem 取得尚可的结果，但我们的模型明显推进了最优水平，强调了"同时准确利用自然语言上下文情境与结构化图表示"对时间推理的关键优势。

### 4.2 跨类别分析

跨不同问题类别的综合评估显示，我们提出的架构 Mem0 与 $\text{Mem0}^{g}$ 相比基线系统一致取得更优性能。对于单跳查询，Mem0 表现尤为强劲，受益于其高效的稠密自然语言记忆结构。尽管 $\text{Mem0}^{g}$ 中的图表示在这些更简单的查询上于词汇重叠类指标上略有落后，但它们显著增强了语义连贯性，这体现在有竞争力的 J 分数上。这表明图结构在涉及细微关系上下文的场景中比在直白检索中更有益。对于多跳问题，Mem0 通过有效综合跨多个会话的分散信息展现出明显优势，证实自然语言记忆为这类整合任务提供了足够的表示丰富度。令人意外的是，$\text{Mem0}^{g}$ 预期中的关系优势在此并未转化为更好的结果，说明在多步推理场景下导航更复杂的图结构时可能存在额外开销或冗余。

在时间推理方面，$\text{Mem0}^{g}$ 大幅优于其他方法，验证了结构化关系图在捕获时序关系与事件序列方面的优越性。显式关系上下文的存在显著增强了 $\text{Mem0}^{g}$ 的时间连贯性，优于 Mem0 的稠密记忆存储，凸显了在跟踪时间敏感信息时精确关系表示的重要性。开放域表现进一步强化了关系建模的价值。$\text{Mem0}^{g}$ 得益于图记忆的关系清晰性，与表现最好的基线（Zep）形成紧密竞争。这一有竞争力的结果凸显了 $\text{Mem0}^{g}$ 通过关系清晰性整合外部知识的稳健性，表明结构化记忆与开放域信息综合之间存在最优协同。

总体而言，我们的分析表明 Mem0 与 $\text{Mem0}^{g}$ 在不同任务需求下具有互补优势：稠密的、基于自然语言的记忆为更简单的查询提供了显著效率，而显式关系建模对于需要细微时间与上下文整合的任务变得不可或缺。这些发现强化了"在 AI 智能体部署中，记忆结构应针对具体推理上下文自适应"这一要点。

### 4.4 延迟分析

表 2 给出了各类检索与记忆方法在 LOCOMO 数据集上检索阶段与总响应生成的全面性能对比，包括中位数（p50）与尾部（p95）延迟。我们的分析揭示了由架构选择所决定的明显性能模式。以记忆为中心的架构表现出不同的性能特征：A-Mem 尽管记忆存储更大，却承受了可观的检索开销（p50：0.668 s），导致总中位延迟为 1.410 s；LangMem 的检索延迟更高（p50：17.99 s，p95：59.82 s），使其在交互式应用中不具实用性；Zep 取得中等表现（总延迟 p50：1.292 s）。

全上下文基线不进行检索、直接处理整段对话历史，与基于检索的方法有本质不同。通过把整段对话上下文（26000 tokens）直接传给 LLM，它消除了检索开销，但承受了极端的总体延迟（p50：9.870 s，p95：17.117 s）。类似地，OpenAI 的实现不执行记忆检索，因为它处理的是从其 playground 中**手工抽取**的记忆。虽然这一方法取得了令人印象深刻的响应生成时间（p50：0.466 s，p95：0.889 s），但它需要预先抽取相关上下文，而这一成本并未反映在报告的指标中。

我们提出的 Mem0 方法在所有方法中取得最低的检索延迟（p50：0.148 s，p95：0.200 s），如图 4(a) 所示。这一效率源于我们的选择性记忆检索机制与基础设施改进——它动态识别并只检索最显著的信息，而非固定大小的分块。因此，Mem0 保持了最低的总中位延迟（0.708 s）与极为可控的 p95 值（1.440 s），使其特别适合交互式 AI 智能体等延迟敏感应用。图增强的 $\text{Mem0}^{g}$ 变体以适度的延迟代价引入了额外的关系建模能力，其检索时间（0.476 s）仍优于所有现有记忆方案与基线。尽管有所增加，$\text{Mem0}^{g}$ 仍保持有竞争力的总延迟（p50：1.091 s，p95：2.590 s），同时在所有方法中取得最高 J 分数（68.44%）——仅次于计算上难以承受的全上下文方法。这一性能画像展示了我们的方法在回复质量与计算效率之间取得平衡的能力，为二者都是关键约束的生产级 AI 智能体提供了极具吸引力的方案。

### 4.5 记忆系统开销：Token 分析与构建时间

我们测量了实体化（materialise）各系统长期记忆库所需的平均 token 预算。Mem0 把完整对话轮次编码为自然语言表示，因此每段对话平均只占用 **7k tokens**；而 $\text{Mem0}^{g}$ 约为前者的两倍，达到 **14k tokens**，原因是引入了包含节点及对应关系的图记忆。形成鲜明对比的是，Zep 的记忆图消耗 **超过 600k tokens**。这种膨胀源于 Zep 的设计选择：在每个节点缓存完整的摘要式（abstractive）总结，同时在连接边上也存储事实，导致图中出现大量冗余。作为参照，把整段原始对话上下文——不做任何记忆抽象——直接提供给语言模型，平均约 26k tokens，比 Zep 的图少 20 倍。

除 token 效率低下之外，我们的实验还揭示了 Zep 在运行层面的显著瓶颈。在向 Zep 系统添加记忆后，我们观察到立即尝试记忆检索往往无法正确回答查询；而有趣的是，延迟数小时后重跑相同检索会得到明显更好的结果。这种延迟说明 Zep 的图构建涉及多次异步 LLM 调用与大量后台处理，使该记忆系统对实时应用不具实用性。相比之下，Mem0 的图构建即便在最坏情况下也能在一分钟内完成，使用户能够立即利用新加入的记忆来回答查询。

> *（译者注）* 这段是全文对 Zep 最实质的批评：**"写完读不到"**（write-then-read 不一致）比 token 膨胀更致命——它意味着系统存在最终一致性（eventual consistency）窗口，而对话式 AI 的默认假设是强一致。

这些发现表明，Zep 不仅在多个节点上复制了相同的知识片段，还引入了显著的操作延迟。我们的架构——Mem0 与 $\text{Mem0}^{g}$——以一小部分 token 成本、且记忆可用性显著更快的方式，保存了相同的信息，提供了更省记忆、运行响应更及时的一种表示。

## 5 结论与未来工作

我们提出了 Mem0 与 $\text{Mem0}^{g}$，两种互补的记忆架构，克服了 LLM 固定上下文窗口的内在局限。通过动态抽取、整合与检索紧凑的记忆表示，Mem0 在单跳与多跳推理上取得最优性能，而 $\text{Mem0}^{g}$ 的图扩展在时间与开放域任务上带来显著增益。在 LOCOMO 基准上，相比各问题类型中表现最好的方法，我们的方法在单跳、时间与多跳推理问题类型上分别取得 **5%、11% 与 7% 的相对提升**，并且相比全上下文基线把 **p95 延迟降低 91% 以上**——展示了精度与响应性之间的强大平衡。

Mem0 的稠密记忆流水线擅长为直白查询做快速检索，将 token 用量与计算开销降至最低。相比之下，$\text{Mem0}^{g}$ 的结构化图表示提供了细微的关系清晰性，在不牺牲实用效率的前提下支持复杂事件排序与丰富的上下文整合。二者共同构成一套多功能的记忆工具包：它能适应多样化的对话需求，同时保持可规模化部署。

未来的研究方向包括：优化图操作以降低 $\text{Mem0}^{g}$ 的延迟开销；探索兼顾效率与关系表示的分层记忆架构；以及受人类认知过程启发，开发更精细的记忆整合机制。此外，把我们的记忆框架扩展到对话场景之外的领域——例如过程性推理（procedural reasoning）与多模态交互——将进一步验证其更广泛的适用性。通过解决固定上下文窗口这一根本局限，我们的工作代表着朝向"能够在长时间跨度上维持连贯、上下文丰富的交互、如同人类一般"的对话式 AI 系统的重要进展。

## 附录 B 算法

**算法 1 记忆管理系统：更新操作**

```
输入: 检索到的记忆集合 F, 既有记忆库 M = {m1, m2, ..., mn}
输出: 更新后的记忆库 M'

procedure UpdateMemory(F, M)
  for each fact f ∈ F do
    operation ← ClassifyOperation(f, M)        ⊳ 依据分类执行相应操作
    if operation = ADD then
      id ← GenerateUniqueID()
      M ← M ∪ {(id, f, "ADD")}                 ⊳ 以唯一标识符添加新事实
    else if operation = UPDATE then
      mi ← FindRelatedMemory(f, M)
      if InformationContent(f) > InformationContent(mi) then
        M ← (M \ {mi}) ∪ {(id_i, f, "UPDATE")}  ⊳ 用更丰富的信息替换
      end if
    else if operation = DELETE then
      mi ← FindContradictedMemory(f, M)
      M ← M \ {mi}                             ⊳ 移除被矛盾的信息
    else if operation = NOOP then
      不执行任何操作                              ⊳ 事实已存在或不相关
    end if
  end for
  return M
end procedure

function ClassifyOperation(f, M)
  if ¬SemanticallySimilar(f, M) then
    return ADD         ⊳ 记忆中不存在的新信息
  else if Contradicts(f, M) then
    return DELETE      ⊳ 信息与既有记忆冲突
  else if Augments(f, M) then
    return UPDATE      ⊳ 增强记忆中的既有信息
  else
    return NOOP        ⊳ 无需改动
  end if
end function
```

> *（译者注）* 这段伪代码给出了 Mem0 更新阶段的完整契约：**分类函数**只做语义关系判定（不相似→ADD、矛盾→DELETE、可增强→UPDATE、否则 NOOP），**执行函数**负责真正的增删改。注意 UPDATE 分支带了一个 `InformationContent` 守卫——只有当新事实信息量更大时才覆盖旧记忆，避免用更弱的表述冲掉更强的表述。

## 附录 C 入选基线详解

**LoCoMo**

LoCoMo 框架实现了一套精细的记忆流水线，使 LLM 智能体能够维持连贯的长期对话。其核心是把记忆划分为**短期**与**长期**两部分。每个对话会话结束后，智能体生成摘要（作为短期记忆存储），提炼该次交互的关键信息。同时，单个对话轮次被转换为**观察**（observation）——关于每位说话者人设与生活事件的事实性陈述，存入长期记忆并附带产生它们的特定对话轮次引用。在生成新回复时，智能体同时利用最近一次会话摘要，以及从长期记忆中按需检索的相关观察。这种双记忆方法进一步由一个**时间事件图**增强，用来追踪发生在各对话会话之间、具有因果关联的生活事件。通过把回复建立在检索到的记忆、当前对话上下文、人设信息与期间发生的生活事件之上，该系统使智能体能够在跨越数百轮、数十个会话的对话中维持一致人格并回忆重要细节。

**ReadAgent**

ReadAgent 通过模拟人类处理长文本的方式，用一套精细的三阶段流水线应对 LLM 的根本局限。第一阶段是**情节分页**（Episode Pagination）：系统在自然的认知边界而非任意截断处智能切分文本。第二阶段是**记忆要点化**（Memory Gisting）：把每个片段提炼为简洁摘要，在保留基本含义的同时大幅减少 token 数量——类似人类记忆保留信息的实质而非逐字回忆。最后，在被要求回答问题时，**交互式查找**（Interactive Lookup）机制审视这些要点，并策略性地只检索最相关的原始文本片段做细致处理。这种受人类启发的做法使 LLM 能够有效处理比其常规上下文窗口长 20 倍的文档。通过在"要点提供的全局理解"与"对细节的选择性注意"之间取得平衡，ReadAgent 同时获得了计算效率与理解力提升，证明模仿人类认知过程可以显著增强 AI 的文本处理能力。

**MemoryBank**

MemoryBank 系统通过一套精细的三部分流水线为 LLM 增强长期记忆。其核心是**记忆存储**（Memory Storage）组件，仓库化保存详细对话日志、分层事件摘要与不断演化的用户人格画像。当新交互发生时，**记忆检索**（Memory Retrieval）机制采用双塔稠密检索模型（dual-tower dense retrieval）抽取上下文相关的过往信息。**记忆更新**（Memory Updating）组件提供了类人的遗忘机制：记忆在被回忆时增强，若长期不用则自然衰减。这一综合方法使 AI 伴侣能够回忆相关信息、在长时间交互中保持上下文感知、并发展出越来越准确的用户画像，从而实现更个性化、更自然的长期对话。

**MemGPT**

MemGPT 系统引入了一种受操作系统启发的方法，以克服 LLM 固有的上下文窗口限制。其核心是一套精细的记忆管理流水线，由三个关键组件构成：**分层记忆系统**、**自主导向的记忆操作**与**基于事件的控制流机制**。系统把可用记忆划分为"主上下文"（main context，类比传统 OS 中的 RAM）与"外部上下文"（external context，类比磁盘存储）。主上下文——受 LLM 上下文窗口约束——包含系统指令、最近对话历史与可被模型修改的工作记忆。外部上下文在模型即时上下文窗口之外存储无限信息，包括完整对话历史与归档数据。当 LLM 需要主上下文中不存在的信息时，它可以发起函数调用，在这些记忆层级间搜索、检索或修改内容，从而有效地把相关信息"分页"进出其有限上下文窗口。这一受 OS 启发的架构使 MemGPT 能够在长时间交互中维持对话连贯性、管理超出标准上下文限制的文档、并执行多跳信息检索任务——而这一切都是在定长上下文模型上完成的。系统智能管理自身记忆资源的能力提供了"无限上下文"的假象，显著扩展了当前 LLM 技术所能达到的边界。

**A-Mem**

A-Mem 模型为 LLM 智能体引入了一种智能体式记忆系统。该系统通过相互连接的笔记（note）动态地组织与演化记忆。每条笔记捕获一次交互，并由 LLM 生成关键词、上下文描述与标签等结构化属性加以丰富。在创建新记忆时，A-MEM 使用语义嵌入检索相关既有笔记，然后采用 LLM 驱动的方法，基于相似性与共享属性建立有意义的链接。关键在于，**记忆演化**（memory evolution）机制会动态更新既有笔记，在新相关记忆被整合时细化其上下文信息与属性。因此，记忆结构持续演化，使记忆之间形成更丰富、上下文更深的连接。记忆检索通过语义相似度完成，在智能体交互过程中提供相关的历史上下文。
