## 摘要

近期的工作通过为大语言模型（LLM）接入外部资源（例如互联网）或内部的控制流（例如提示链，prompt chaining），来应对需要"接地"（grounding）或推理的任务，由此催生了一类新的系统：语言智能体（language agents）。尽管这类智能体已取得大量实证成功，我们仍缺少一个系统性的框架来组织已有智能体、并规划未来的发展方向。

本文借助认知科学（cognitive science）与符号人工智能（symbolic AI）的深厚历史，提出**语言智能体的认知架构（Cognitive Architectures for Language Agents, CoALA）**。CoALA 描述的语言智能体具有：模块化的记忆组件、用于与内部记忆和外部环境交互的结构化动作空间，以及用于选择动作的泛化决策过程。

我们用 CoALA 回溯性地梳理并组织了大量近期工作，并前瞻性地指出了通往更强智能体的可操作方向。总体而言，CoALA 把当下的语言智能体放回人工智能的 broader 历史脉络中加以定位，并勾勒出一条通向"基于语言"的通用智能的路径。

## 1 引言

**语言智能体**（language agents，Weng, 2023; Wang et al., 2023b; Xi et al., 2023; Yao and Narasimhan, 2023）是一类新兴的人工智能（AI）系统，它们使用大语言模型（Vaswani et al., 2017; Brown et al., 2020; Devlin et al., 2019; OpenAI, 2023a）来与世界交互。这类系统把 LLM 的最新进展应用到既有的智能体设计领域（Russell and Norvig, 2013）之中。

有趣的是，这种综合对两个领域都有好处。一方面，LLM 的知识与推理能力是有限的；语言智能体通过把 LLM 连接到内部记忆和环境，将其"接地"到已有知识或外部观测上，从而缓解这些问题。另一方面，传统智能体往往需要人工编写的规则（Wilkins, 2014）或强化学习（Sutton and Barto, 2018），难以泛化到新环境（Lake et al., 2016）；语言智能体则利用 LLM 中蕴含的常识先验来适应新任务，减少了对人工标注或试错学习的依赖。

最早的智能体直接用 LLM 选择或生成动作（Ahn et al., 2022; Huang et al., 2022b，图 1B）；而更近期的智能体还额外用 LLM 进行**推理**（Yao et al., 2022b）、**规划**（Hao et al., 2023; Yao et al., 2023）和**长期记忆管理**（Park et al., 2023; Wang et al., 2023a），以改进决策。这最新一代的**认知语言智能体**（cognitive language agents）使用了相当精巧的内部过程（图 1C）。

然而目前，各个工作用各自定制的术语来描述这些过程（如"工具使用""接地""动作"），导致我们很难比较不同智能体、理解它们如何随时间演进，也很难用干净、一致的抽象来构建新的智能体。

为了建立一个组织这些工作的概念框架，我们类比了计算与人工智能史上的两个概念：**产生式系统**（production systems）与**认知架构**（cognitive architectures）。产生式系统通过迭代地应用规则来生成一组结果（Newell and Simon, 1972）。它最初是作为字符串改写系统提出的——这正是 LLM 所解决问题的类比物——随后被 AI 社区采纳，用于定义能够执行复杂、层次化行为的系统（Newell et al., 1989）。为此，产生式系统被纳入到**认知架构**中，由认知架构来规定选择、应用乃至生成新产生式的控制流（Laird et al., 1987; Laird, 2022; Kotseruba and Tsotsos, 2020）。

我们认为产生式系统与 LLM 之间存在一个有意义的类比：正如产生式指明了修改字符串的可能方式，LLM 定义了文本变化或增补上的一个分布。这进一步暗示：认知架构中用于产生式系统的那些控制机制，也许同样适用于把 LLM 改造为语言智能体。

> **图 1｜大语言模型（LLM）的三种不同用法。**
> **A**：在自然语言处理（NLP）中，LLM 以文本为输入、输出文本。
> **B**：语言智能体（Ahn et al., 2022; Huang et al., 2022c）把 LLM 置于与外部环境的直接反馈回路中：把观测转换为文本，再用 LLM 选择动作。
> **C**：认知语言智能体（Yao et al., 2022b; Shinn et al., 2023; Wang et al., 2023a）还额外用 LLM 通过推理、学习等过程来管理智能体的内部状态。本文提出的正是为这类智能体提供结构蓝图的框架。
>
> *（译者注）* 图中实质上画的是三层递进：A 是一次函数调用（文本进、文本出）；B 引入了"环境—观测—动作"闭环；C 在闭环内部又加了一层"内部状态管理"，即 LLM 既对外决策也对内改记忆。

因此，我们提出**语言智能体的认知架构（CoALA）**，一个用于刻画与设计通用语言智能体的概念框架。CoALA 沿三个关键维度组织智能体：**信息存储**（划分为工作记忆与长期记忆）、**动作空间**（划分为内部动作与外部动作）、**决策过程**（结构为带"规划—执行"的交互式循环）。通过记忆、动作、决策这三个概念，我们展示 CoALA 能干净地表达大量已有智能体，并识别出尚未被充分探索、可用于发展新智能体的方向。

值得注意的是，尽管近期已有若干论文提出了面向通用智能的概念性架构（LeCun, 2022; McClelland et al., 2019），或对语言模型与智能体做了实证综述（Mialon et al., 2023; Weng, 2023; Wang et al., 2023b），本文则把两者结合起来：我们提出一个理论框架，并用它来组织多样化的实证工作。这使我们的理论扎根于现有实践，同时让我们能同时识别短期的与长期的研究方向。

全文安排如下：第 2 节介绍产生式系统与认知架构；第 3 节说明 LLM 与语言智能体的近期发展如何"重演"了这些历史思想；受这些类比的启发，第 4 节提出 CoALA 框架并用它来综述现有语言智能体；第 5 节对若干代表性智能体做更深入的案例研究；第 6 节给出构建未来语言智能体的可操作步骤；第 7 节讨论认知科学与 AI 更大图景中的开放问题；第 8 节总结。关注应用型智能体设计的读者可优先阅读第 4–6 节。

## 2 背景：从字符串到符号通用人工智能

我们先介绍产生式系统与认知架构，给出一条关于认知科学与人工智能的历史线索：从逻辑与计算的理论（Post, 1943）开始，一直到构建符号式通用人工智能（symbolic AGI）的尝试（Newell et al., 1989）。随后简要介绍语言模型与语言智能体。第 3 节将把这些线索连接起来，在产生式系统与语言模型之间建立类比。

### 2.1 用于字符串改写的产生式系统

二十世纪上半叶，一条重要的思想脉络把数学（Whitehead and Russell, 1997）与计算（Church, 1932; Turing et al., 1936）归约为符号操作。产生式系统就是其中一种形式化体系。

直观地说，产生式系统由一组规则组成，每条规则指定一个**前置条件**（precondition）与一个**动作**（action）；当前置条件满足时，动作即可被执行。这一思想源自刻画"计算的极限"的努力。Post（1943）提出用这种方式来思考任意的逻辑系统：公式被表示为字符串，而它们所允许的结论由产生式规则识别（即一个字符串"产生"另一个字符串）。这一表述随后被证明等价于一个更简单的**字符串改写系统**（string rewriting system）。在这类系统中，我们指定形如

$$X\,Y\,Z \rightarrow X\,W\,Z$$

的规则，表示字符串 $XYZ$ 可被改写为字符串 $XWZ$。字符串改写在形式语言理论中扮演着重要角色，例如乔姆斯基的短语结构语法（Chomsky, 1956）。

### 2.2 控制流：从字符串到算法

### 2.3 认知架构：从算法到智能体

产生式系统是由 Allen Newell 在 AI 社区中推广开来的，他当时在寻找一种能刻画人类问题求解的形式化体系（Newell, 1967; Newell and Simon, 1972）。产生式被从字符串改写推广到**逻辑操作**：前置条件可以针对智能体的目标与世界状态进行检查，而动作则在条件满足时被执行。

在其里程碑著作《Human Problem Solving》（Newell and Simon, 1972）中，Newell 与 Simon 给出了一个实现"恒温器智能体"的简单产生式系统示例：

| 前置条件 | 动作 |
| --- | --- |
| $(\text{temperature} > 70^\circ) \wedge (\text{temperature} < 72^\circ)$ | 停止（stop） |
| $\text{temperature} < 32^\circ$ | 呼叫维修；打开电暖器 |
| $(\text{temperature} < 70^\circ) \wedge (\text{furnace off})$ | 打开锅炉 |
| $(\text{temperature} > 72^\circ) \wedge (\text{furnace on})$ | 关闭锅炉 |

在这项工作之后，产生式系统被 AI 社区广泛采纳。由此得到的智能体包含大规模的产生式系统，并与外部传感器、执行器和知识库相连——这相应要求更精巧的控制流。AI 研究者定义了**认知架构**，模仿人类认知，显式地实例化感知、记忆、规划等过程（Adams et al., 2012），以实现灵活、理性、实时的行为（Sun, 2004; Newell, 1980, 1992; Anderson and Lebiere, 2003）。这带来了从心理建模到机器人学的众多应用，产生了数以百计的架构与数以千计的论文（近期综述见 Kotseruba and Tsotsos, 2020）。

一个经典例子是 **Soar** 架构（图 2A）。Soar 把产生式存放在长期记忆中，并依据其前置条件与工作记忆的匹配程度来执行它们（图 2B）。这些产生式指定了会修改工作记忆与长期记忆内容的动作。下面我们简要概述 Soar，更深入的介绍请读者参阅 Laird（2022, 2019）。

**记忆。** 建立在心理学理论之上，Soar 使用多种类型的记忆来追踪智能体状态（Atkinson and Shiffrin, 1968）。**工作记忆**（Baddeley and Hitch, 1974）反映智能体当前所处的境况：它存储智能体近期的感知输入、目标，以及中间内部推理的结果。**长期记忆**分为三种不同类型：**程序性记忆**（procedural memory）存放产生式系统本身，即那些可作用于工作记忆以决定智能体行为的规则集合；**语义记忆**（semantic memory）存放关于世界的事实（Lindes and Laird, 2016）；**情景记忆**（episodic memory）存放智能体过往行为的序列（Nuxoll and Laird, 2007）。

> **图 2｜认知架构在产生式系统之上增加了感知接地、长期记忆与动作选择决策程序。**
> **A**：Soar 架构（经 Laird, 2022 许可转载）。图中从左到右大致是：感知/传感器 → 工作记忆 → 与长期记忆（程序性/语义/情景）交互 → 决策程序 → 动作输出/执行器。
> **B**：Soar 的决策程序用产生式来选择并实施动作。这些动作既可能是内部的（如修改智能体的记忆），也可能是外部的（如一条运动指令）。

**接地。** Soar 可以在仿真环境中实例化（Tambe et al., 1995; Jones et al., 1999），也可以部署在真实世界的机器人系统上（Laird et al., 2012）。在具身情境中，多种传感器把感知输入流式写入工作记忆，供决策使用。Soar 智能体还可以配备执行器，从而能够执行物理动作，并通过语言进行交互式学习（Mohan et al., 2012; Mohan and Laird, 2014; Kirk and Laird, 2014）。

**决策。** Soar 实现了一个决策循环：评估各产生式，并应用匹配最好的那一个（图 2B）。产生式存放在长期程序性记忆中；在每个决策周期内，其前置条件会与智能体的工作记忆进行匹配。在"提议与评估"阶段，一组产生式被用来生成候选动作集并对其排序。

> **脚注**：更具体地说，Soar 把产生式分为两类："算子"（operators，本文称为动作）与"规则"（rules，用于提议、评估和执行算子）。随后选出最佳动作。

如果没有任何动作有效，或出现多个动作并列，就会发生**僵局**（impasse）。此时 Soar 会创建一个子目标来化解僵局，从而形成层次化任务分解。更详细的讨论请参阅 Laird（2022）。随后另一组产生式被用来实施该动作——例如修改工作记忆的内容，或发出运动指令。

**学习。** Soar 支持多种学习模式。第一，新信息可以直接写入长期记忆：事实可写入语义记忆，经验可写入情景记忆（Derbinsky et al., 2012）；这些信息之后在需要决策时可被检索回工作记忆。第二，行为可以被修改：强化学习（Sutton and Barto, 2018）可以为带来良好结果的产生式提高权重，使智能体从经验中学习（Nason and Laird, 2005）。最引人注目的是，Soar 还能把新的产生式写入自己的程序性记忆（Laird et al., 1986）——实质上是在更新自己的源代码。

认知架构曾广泛用于心理学与计算机科学，应用包括机器人（Laird et al., 2012）、军事仿真（Jones et al., 1999; Tambe et al., 1995）与智能教学（Koedinger et al., 1997）。然而在过去几十年里，它们在 AI 社区中的热度逐渐下降。这种降温反映了此类系统的两个挑战：它们局限于可用逻辑谓词描述的领域，并且需要大量预先指定的规则才能运转。

有趣的是，LLM 似乎恰好能应对这两个挑战：第一，它们作用于任意文本，比基于逻辑的系统更灵活；第二，它们不需要用户指定产生式，而是通过在海量互联网语料上预训练，学得了一个产生式上的分布。认识到这一点，研究者已开始把 LLM 用于认知架构之中，利用其隐含的世界知识（Wray et al., 2021）来增强传统符号方法（Kirk et al., 2023; Romero et al., 2023）。而本文的取向相反：我们引入认知架构的原则，来指导基于 LLM 的智能体的设计。

### 2.4 语言模型与智能体

语言建模是 NLP 与 AI 社区数十年来的课题，目标是构建能在给定上下文下生成文本的系统（Jurafsky, 2000）。形式上，语言模型学习一个分布 $P(w_i \mid w_{<i})$，其中每个 $w$ 是一个词元（token）。随后模型可以通过从该分布中采样、每次一个 token 的方式来生成文本。在其核心意义上，语言模型是一个**概率性的输入—输出系统**，因为文本的续写方式本质上存在多种可能（例如 "I went to the" → "market" | "beach" | …）。早期建模语言的尝试（如 n-gram）在泛化与扩展性上面临困难；近年来，由于基于 Transformer（Vaswani et al., 2017）、参数量达数十亿的 LLM 的兴起（如 GPT-4，OpenAI, 2023a）以及更聪明的分词方案，该领域重新活跃起来。现代 LLM 在海量数据上训练，这帮助它们从大量输入—输出组合中积累知识，并成功生成类人的文本（Andreas, 2022）。

出乎意料的是，在互联网规模文本上训练这些模型，也使它们在生成文本之外的许多任务上有用，例如写代码（Li et al., 2022b; Rozière et al., 2023; Li et al., 2023c）、蛋白质建模（Meier et al., 2021），以及在交互式环境中行动（Yao et al., 2022b; Nakano et al., 2021）。后者促成了**语言智能体**的兴起——以 LLM 为核心计算单元来进行推理、规划与行动的系统——应用于机器人（Ahn et al., 2022）、制造（Xia et al., 2023）、网页操作（Yao et al., 2022a; Deng et al., 2023）、解谜（Yao et al., 2023; Hao et al., 2023）与交互式代码生成（Yang et al., 2023）等领域。语言理解与决策能力的结合是一个激动人心的新兴方向，有望让这些智能体更接近类人的智能。

## 3 语言模型与产生式系统之间的联系

基于二者在处理字符串上的同源起点，产生式系统与语言模型之间存在一个自然的类比。我们先发展这个类比，然后说明各类提示方法实际上"重演"了基于产生式系统的算法与智能体。产生式系统与语言模型之间的对应关系，正是我们采用认知架构来构建语言智能体的动因，这将在第 4 节展开。

### 3.1 语言模型作为概率产生式系统

在其最初的实例化形式中，产生式系统指定了从某个起点出发所能生成的字符串集合，并把这一过程分解为一系列字符串改写操作。语言模型同样定义了字符串的一种可能扩展或修改集合——这个字符串就是提供给模型的提示（prompt）。

> **脚注**：本文聚焦于语言智能体常用的自回归 LLM。不过像 BERT（Devlin et al., 2019）这样的双向 LLM 也可作类似理解：它们定义的是"填充式"（in-filling）产生式上的分布。

例如，我们可以把"补全一段文本"这件事表述为一条产生式。若 $X$ 是提示、$Y$ 是续写，则可写作产生式 $X \rightarrow X\,Y$。

> **脚注**：另一种做法是把提示视为输入、把 LLM 的输出视为下一状态，用产生式 $X \rightarrow Y$ 表示，这是一种更字面意义上的改写。若希望允许多种可能续写，则得到 $X \rightarrow X\,Y_i$，其中 $Y_i$ 属于某个集合。LLM 为每一种续写赋予概率。

从这个视角看，LLM 定义了"给定输入 $X$ 时该选哪条产生式"上的概率分布，即可能续写上的分布 $P(Y_i \mid X)$（Dohan et al., 2022）。因此，LLM 可以被视为**概率产生式系统**：每次被调用时采样出一个可能的续写，例如 $X \rightsquigarrow X\,Y$。

与传统产生式系统相比，这种概率形式既带来优势也带来劣势。LLM 的主要劣势在于其固有的**不透明性**：产生式系统由离散且人类可读的规则定义，而 LLM 由数十亿不可解释的参数构成。这种不透明性——再加上其概率形式带来的固有随机性——使得分析和控制其行为变得困难（Romero et al., 2023; Valmeekam et al., 2022）。尽管如此，其规模与预训练带来了远超传统产生式系统的巨大优势：在大规模互联网数据上预训练的 LLM 学得了关于字符串续写的极为有效的先验，使其能够开箱即用地解决广泛的任务（Huang et al., 2022b）。

### 3.2 提示工程作为控制流

LLM 的权重定义了对输出字符串（续写）的一种优先级排序，并以输入字符串（提示）为条件。所得分布可以解释为**任务特定的产生式优先级**——换言之，一种简单的控制流。诸如问答之类的任务可以直接表述为一个输入字符串（问题），从而得到续写（可能的答案）上的条件分布。

**表 1：提示方法如何操纵输入字符串以影响生成。** $Q$ = 问题，$A$ = 答案，$O$ = 观测，$C$ = 批评（critique），$\rightsquigarrow$ 表示从随机产生式中采样。

| 提示方法 | 产生式序列 | 含义 |
| --- | --- | --- |
| Zero-shot（零样本） | $Q \rightsquigarrow Q\,A$ | 直接把问题丢给 LLM 得到答案 |
| Few-shot（少样本） | $Q \longrightarrow Q_1 A_1 Q_2 A_2 Q \rightsquigarrow Q_1 A_1 Q_2 A_2 Q\,A$ | 先在输入中拼入若干示例，再采样答案 |
| Retrieval Augmented Generation（检索增强生成） | $Q \xrightarrow{\text{Wiki}} Q\,O \rightsquigarrow Q\,O\,A$ | 先用检索器取回文档 $O$，再基于 $Q\,O$ 生成答案 |
| Socratic Models（苏格拉底式模型） | $Q \rightsquigarrow_{\text{VLM}} Q\,O \rightsquigarrow_{\text{LLM}} Q\,O\,A$ | 先用视觉语言模型把图像转成文本观测，再交给 LLM |
| Self-Critique（自我批评） | $Q \rightsquigarrow Q\,A \rightsquigarrow Q\,A\,C \rightsquigarrow Q\,A\,C\,A$ | 先作答，再生成批评，再据批评修订答案 |

> 表中"含义"一列为译者补充的说明，原文仅有前两列。

这些预处理式操纵——它们可以使用其它模型（如视觉语言模型 VLM），甚至 LLM 自身——都可以被视为产生式。因此，提示方法实际上定义了**一个产生式序列**。

早期关于少样本学习（Brown et al., 2020）与提示工程（Wei et al., 2022b; Kojima et al., 2022; Xu et al., 2023c）的工作发现：通过对输入字符串做预处理，可以进一步把 LLM 偏置到高质量的产生式上。这些简单的操纵——通常只是把额外的文本拼接到输入上——本身就可视为产生式，因此这些方法定义了一个产生式序列（表 1）。

后续工作把这些方法扩展到动态、上下文敏感的提示：例如选择与输入最相关的少样本示例（Liu et al., 2021），或用来自视频（Zeng et al., 2022）或数据库（Lewis et al., 2020）的外部观测来填充模板。此类提示技术的综述见 Liu et al.（2023d）。

再后来的工作把 LLM 自身用作预处理步骤，引导出有针对性的推理以突出问题的某个方面（Bai et al., 2022; Jin et al., 2022; Ganguli et al., 2023; Madaan et al., 2023; Saunders et al., 2022; Kim et al., 2023; Kirk et al., 2023），或在给出答案前生成中间推理步骤（Tafjord et al., 2021; Creswell et al., 2023; Yao et al., 2023）。把多次 LLM 调用串联起来（Wu et al., 2022a, b; Dohan et al., 2022）则可以实现越来越复杂的算法（图 3）。

> **图 3｜从语言模型到语言智能体。**
> **A**：一次 LLM 调用的基本结构。提示构建（prompt construction）选择一个模板并用工作记忆中的变量填充；调用 LLM 后，输出的字符串被解析进动作空间并执行。一次 LLM 调用可能产生一个或多个动作——例如给出答案、调用函数，或发出运动指令。
> **B**：诸如 Self-Critique（Wang et al., 2022b）或 Selection-Inference（Creswell et al., 2023）这样的提示链技术，使用预先定义好的 LLM 调用序列来生成输出。
> **C**：而 Inner Monologue（Huang et al., 2022c）与 ReAct（Yao et al., 2022b）这样的语言智能体，改用与外部环境的交互式反馈回路。视觉语言模型（VLM）可用于把感知数据转换为文本供 LLM 处理。

### 3.3 走向认知语言智能体

语言智能体不再依赖预先定义的提示链，而是把 LLM 置于与外部环境的反馈回路中（图 1B）。这类方法先把多模态输入转换为文本并传给 LLM，LLM 的输出随后被解析，用于确定一个外部动作（图 3C）。早期智能体让 LLM 直接与外部环境对接，依据智能体状态产生高层指令（Ahn et al., 2022; Huang et al., 2022c; Dasgupta et al., 2022）。后续工作发展出更精巧的语言智能体，先用 LLM 进行中间推理，再选择动作（Yao et al., 2022b）。最新的一批智能体引入了精巧的学习策略，例如反思情景记忆以生成新的语义推论（Shinn et al., 2023），或修改自身程序代码以生成程序性知识（Wang et al., 2023a），从而利用过去的经验调整未来的行为。

这些**认知语言智能体**使用了非平凡的、基于 LLM 的推理与学习（图 1C）。正如认知架构曾用于组织产生式系统与智能体内部状态、外部环境之间的交互，我们认为它们同样可以帮助设计基于 LLM 的认知智能体。在本文余下部分，我们用这一视角组织现有方法，并指出有前景的扩展方向。

> **图 4｜语言智能体的认知架构（CoALA）。**
> **A**：CoALA 定义了一组相互作用的模块与过程。决策程序（decision procedure）执行智能体的"源代码"。该源代码由若干过程组成：与 LLM 交互的过程（提示模板与解析器）、与内部记忆交互的过程（检索与学习）、以及与外部环境交互的过程（接地）。
> **B**：在时间维度上，智能体的决策程序与外部环境构成一个循环，反复执行**决策周期**。每个周期中，智能体通过检索与推理进行**规划**：提议并评估候选的**学习**或**接地**动作，随后选出并执行最佳动作；可能产生一次**观测**，然后循环重新开始。
>
> *（译者注）* 图 4 是全文的核心图：A 是"横截面"（系统由哪些部件构成），B 是"时间轴"（一个决策周期怎么跑）。后文第 4 节的小节顺序基本就是按 A 的部件顺序展开的。

## 4 语言智能体的认知架构（CoALA）：一个概念框架

我们提出 CoALA 作为一个框架，用来组织现有语言智能体并指导开发新的智能体。CoALA 把 LLM 定位为一个更大的认知架构的核心组件（图 4）。在 CoALA 下，语言智能体把信息存放在**记忆模块**中（4.1 节），并在一个分为外部与内部两部分的**动作空间**中行动（图 5）：

- **外部动作**通过**接地**（grounding）与外部环境交互（如控制机器人、与人交流、浏览网站；4.2 节）。
- **内部动作**与内部记忆交互。依据访问的是哪块记忆、访问是读还是写，内部动作可进一步分解为三类：**检索**（从长期记忆读取；4.3 节）、**推理**（用 LLM 更新短期工作记忆；4.4 节）、**学习**（写入长期记忆；4.5 节）。

语言智能体通过**决策**来选择动作，决策遵循一个重复的周期（4.6 节，图 4B）。在每个周期中，智能体可以用推理与检索动作进行**规划**；这个规划子过程会选出一个接地动作或学习动作，并执行它，从而影响外部世界或智能体的长期记忆。CoALA 的决策周期类似于程序的 "main" 过程（一个没有返回值的、持续循环运行的方法）：它不断接受新的感知输入，并据此调用各种动作过程。

CoALA（图 4）受到数十年来认知架构研究的启发（2.3 节），沿用了记忆、接地、学习、决策等核心概念。不过，引入 LLM 带来了新增的**"推理"动作**，它可以灵活地为各种目的产出新知识与启发式——从而取代传统认知架构中手写的规则。它也使文本成为事实上的内部表示，简化了智能体的记忆模块。最后，视觉语言模型（Alayrac et al., 2022）的近期进展可以简化接地：它能把感知数据直接翻译为文本（Zeng et al., 2022）。

本节余下部分详述 CoALA 中的关键概念：记忆、动作（接地、推理、检索、学习）与决策。对每个概念，我们以现有语言智能体（或相关的 NLP/RL 方法）为例加以说明，或指出文献中的空白以作为未来方向。

### 4.1 记忆

语言模型是**无状态**的：它们不跨调用保存信息。相反，语言智能体可以内部存储并维护信息，以支持与世界进行多步交互。在 CoALA 框架下，语言智能体显式地把信息（主要是文本，但也允许其它模态）组织进多个记忆模块，每个模块包含不同形式的信息。这些模块包括短期的工作记忆，以及若干长期记忆：情景记忆、语义记忆与程序性记忆。

**工作记忆（Working memory）。** 工作记忆以符号变量的形式维护当前决策周期（4.6 节）中活跃且随手可取的信息，包括感知输入、活跃知识（由推理生成或从长期记忆检索而来），以及从上一决策周期结转下来的其它核心信息（例如智能体的活跃目标）。以往的方法鼓励 LLM 生成中间推理（Wei et al., 2022b; Nye et al., 2021），把 LLM 自身的上下文当作一种工作记忆。CoALA 的工作记忆概念更一般：它是一个能跨多次 LLM 调用持续存在的数据结构。每次调用 LLM 时，输入由工作记忆的某个子集合成（例如一个提示模板与相关变量）；LLM 的输出随后被解析回其它变量（例如一个动作名与参数），这些变量被存回工作记忆，并用于执行相应动作（图 3A）。除了与 LLM 交互，工作记忆还与长期记忆及接地接口交互，因此它是连接语言智能体各组件的中枢。

> **图 5｜智能体的动作空间可分为对内部记忆的访问与对外部世界的交互。** 推理与检索动作用于支撑规划。图中左侧为"内部动作"（检索 read from LTM、推理 read/write WM、学习 write to LTM），右侧为"外部动作"（接地 → 环境 → 观测回流）。
>
> *（译者注）* 把图 5 与 4.1 节的四种记忆对照着看，就是一张完整的读写矩阵：工作记忆被推理读写，长期记忆被检索读、被学习写。

**情景记忆（Episodic memory）。** 情景记忆存储先前决策周期中的经验，可以是训练用的输入—输出对（Rubin et al., 2021）、历史事件流（Weston et al., 2014; Park et al., 2023）、此前回合的游戏轨迹（Yao et al., 2020; Tuyls et al., 2022），或智能体经验的其他表示形式。在决策周期的规划阶段，这些情景可被检索进工作记忆以支持推理。智能体也可以把新经验从工作记忆写入情景记忆，作为一种学习（4.5 节）。

**语义记忆（Semantic memory）。** 语义记忆存储智能体关于世界以及关于自身的知识。传统上，利用检索来做推理或决策的 NLP/RL 方法，会从外部数据库初始化语义记忆以获得知识支持。例如 NLP 中的检索增强方法（Lewis et al., 2020; Borgeaud et al., 2022; Chen et al., 2017）可以视为从"非结构化文本（如维基百科）的语义记忆"中检索；在 RL 中，"通过阅读来学习"（reading to learn）的方法（Branavan et al., 2012; Narasimhan et al., 2018; Hanjie et al., 2021; Zhong et al., 2021）把游戏手册与事实作为语义记忆来影响策略。这些例子本质上使用的是固定的、只读的语义记忆；而语言智能体还可以把由 LLM 推理获得的新知识写入语义记忆作为学习（4.5 节），从而从经验中逐步积累世界知识。

**程序性记忆（Procedural memory）。** 语言智能体包含两种形式的程序性记忆：存储在 LLM 权重中的隐性知识，以及写在智能体代码中的显性知识。智能体的代码可再分为两类：实现动作的过程（推理、检索、接地与学习过程），以及实现决策本身的过程（4.6 节）。在决策周期中，LLM 可通过推理动作被访问，各种基于代码的过程可被检索并执行。与情景记忆或语义记忆可能初始为空甚至缺失不同，程序性记忆必须由设计者用合适的代码初始化，以"启动"智能体。最后，虽然通过写入程序性记忆来学习新动作是可能的（4.5 节），但这比写入情景记忆或语义记忆风险大得多——它很容易引入缺陷，或让智能体背离设计者的意图。

### 4.2 接地动作（Grounding actions）

接地过程执行外部动作，并把环境反馈处理成文本写入工作记忆。这有效地把智能体与外界的交互简化为一场"文本游戏"：观测是文本，动作也是文本。我们把外部环境分为三类：

**物理环境。** 物理具身是 AI 智能体最早被设想的形态（Nilsson, 1984）。它涉及把感知输入（视觉、听觉、触觉）处理为文本观测（例如通过预训练的描述生成模型），并通过接受语言指令的机器人规划器来影响物理环境。LLM 的近期进展催生了大量机器人项目（Ahn et al., 2022; Liang et al., 2023a; Singh et al., 2023; Palo et al., 2023; Ren et al., 2023），把 LLM 当作机器人的"大脑"，在物理世界中生成动作或计划。对于感知输入，通常使用视觉语言模型把图像转换为文本（Alayrac et al., 2022; Sumers et al., 2023），为 LLM 提供额外上下文（Driess et al., 2023; Huang et al., 2023; Brohan et al., 2022, 2023）。

**与人类或其他智能体的对话。** 经典的语言交互让智能体能够接受指令（Winograd, 1972; Tellex et al., 2011; Chen and Mooney, 2011; Bisk et al., 2016），或从人身上学习（Nguyen et al., 2021; Sumers et al., 2022, 2021; Wang et al., 2016）。具备语言生成能力的智能体可以请求帮助（Ren et al., 2023; Nguyen et al., 2022b, 2019; Nguyen and Daumé III, 2019）或请求澄清（Biyik and Palan, 2019; Sadigh et al., 2017; Padmakumar et al., 2022; Thomason et al., 2020; Narayan-Chen et al., 2019），也可以娱乐或提供情感支持（Zhang et al., 2020; Zhou et al., 2018; Pataranutaporn et al., 2021; Hasan et al., 2023; Ma et al., 2023）。近期工作还研究多个语言智能体之间的交互，用于社会仿真（Park et al., 2023; Jinxin et al., 2023; Gao et al., 2023）、辩论（Chan et al., 2023; Liang et al., 2023b; Du et al., 2023）、安全改进（Irving et al., 2018）或协作式任务求解（Qian et al., 2023; Wu et al., 2023; Hong et al., 2023a; Dong et al., 2023）。

**数字环境。** 这包括与游戏（Hausknecht et al., 2020; Côté et al., 2019; Shridhar et al., 2020; Wang et al., 2022a; Liu et al., 2023e）、API（Schick et al., 2023; Yao et al., 2022b; Parisi et al., 2022; Tang et al., 2023b）与网站（Shi et al., 2017; Nakano et al., 2021; Yao et al., 2022a; Zhou et al., 2023b; Gur et al., 2023; Deng et al., 2023）交互，也包括通用的代码执行（Yang et al., 2023; Le et al., 2022; Ni et al., 2023）。这种数字化接地比物理交互或人际交互更便宜、更快速，因此是语言智能体的便利试验台，近年来的研究强度不断增加。特别地，对于需要增强外部知识或计算的 NLP 任务，无状态的数字 API（如搜索、计算器、翻译器）常被封装为"工具"（Parisi et al., 2022; Schick et al., 2023; Xu et al., 2023a; Tang et al., 2023b; Qin et al., 2023），可以视为特殊的"一次性"数字环境。

### 4.3 检索动作

在 CoALA 中，**检索过程**（Li et al., 2022a; Gu et al., 2018）把信息从长期记忆读入工作记忆。依据信息与记忆类型的不同，它可以用多种方式实现，例如基于规则、稀疏检索或稠密检索。

例如，Voyager（Wang et al., 2023a）通过稠密检索从技能库中加载基于代码的技能来与 Minecraft 世界交互——本质上是从**程序性记忆**中检索接地过程。Generative Agents（Park et al., 2023）通过近期性（基于规则）、重要性（基于推理）与相关性（基于嵌入）三种得分的组合，从**情景记忆**中检索相关事件。DocPrompting（Zhou et al., 2022a）提出利用库文档辅助代码生成，这可以视为从**语义记忆**中检索知识。尽管检索在人类决策中扮演关键角色（Zhou et al., 2023a; Zhao et al., 2022），自适应且情境特定的召回在语言智能体中仍研究不足。我们在第 6 节建议把决策与检索的原则性整合作为重要的未来方向。

### 4.4 推理动作

推理让语言智能体处理工作记忆的内容以生成新信息。与检索（从长期记忆读入工作记忆）不同，推理是**对工作记忆的读写**。它使智能体能够就最近的观测（Yao et al., 2022b; Peng et al., 2023）、最近的轨迹（Shinn et al., 2023），或从长期记忆检索到的信息（Park et al., 2023）进行总结并提炼洞见。推理可用于支持学习（把结果写入长期记忆），也可用于支持决策（把结果作为后续 LLM 调用的额外上下文）。

### 4.5 学习动作

学习通过把信息写入长期记忆而发生，涵盖一系列多样的过程。

**用经验更新情景记忆。** RL 智能体存储情节轨迹以更新参数化策略（Blundell et al., 2016; Pritzel et al., 2017）或建立非参数化策略（Ecoffet et al., 2019; Tuyls et al., 2022），这是常见做法。对语言智能体而言，情景记忆中新增的经验之后可被检索，作为推理或决策的示例与依据（Weston et al., 2014; Rubin et al., 2021; Park et al., 2023）。

**用知识更新语义记忆。** 近期工作（Shinn et al., 2023; Park et al., 2023）用 LLM 对原始经验进行推理，并把所得推论存入语义记忆。例如 Reflexion（Shinn et al., 2023）用 LLM 反思失败的回合，并把结果（如"厨房里没有洗碗机"）作为语义知识存储，附加到 LLM 上下文以求解后续回合。机器人领域的工作（Chen et al., 2023a）则用视觉语言模型构建环境的语义地图，之后可对其查询以执行指令。

**更新 LLM 参数（程序性记忆）。** LLM 权重代表隐性的程序性知识，可通过在智能体生命周期内的微调使其适配特定领域。这类微调可以通过监督学习（Liu et al., 2023c; Zhang et al., 2023b）或模仿学习（Hussein et al., 2017）、基于环境反馈的强化学习（Sutton and Barto, 2018）、人类反馈（Christiano et al., 2017; Ouyang et al., 2022; Nakano et al., 2021，即 RLHF）或 AI 反馈（Bai et al., 2022; Liu et al., 2023f）来完成。经典的 LLM 自我改进方法（Huang et al., 2022a; Zelikman et al., 2022）使用一致性等外部度量（Wang et al., 2022b）来筛选生成结果用于微调。在强化学习设定下，这可以扩展为使用环境反馈：例如 XTX（Tuyls et al., 2022）定期用情景记忆中高分轨迹微调一个小语言模型，该模型作为稳健的"利用"（exploitation）策略，在随机性下抵达探索前沿。微调智能体的 LLM 是一种代价高昂的学习方式，因此现有研究都会指定学习计划（learning schedule）。不过，随着训练变得更高效——或者当智能体使用更小的、面向子任务的专用 LLM 时——语言智能体也许可以自主决定何时以及如何微调其 LLM。

**更新智能体代码（程序性记忆）。** CoALA 允许智能体更新自己的源代码，从而修改各类过程的实现。这可以细分为：

- **更新推理**（如提示模板；Gao et al., 2020; Zhou et al., 2022b）。例如 APE（Zhou et al., 2022b）从输入—输出示例中推断提示指令，再把这些指令作为 LLM 提示的一部分来辅助求解任务。这样的提示更新可以看作一种"学习如何推理"。
- **更新接地**（如基于代码的技能；Liang et al., 2023a; Ellis et al., 2021; Wang et al., 2023a）。例如 Voyager（Wang et al., 2023a）维护一个技能课程库。值得注意的是，当前方法仅限于创建新的代码技能来与外部环境交互。
- **更新检索。** 据我们所知，这些学习选项在近期语言智能体中尚未被研究。检索通常被视为一种以某种固定实现（如 BM25 或稠密检索）设计好的基础动作，但关于查询/文档扩展（Nogueira et al., 2019; Wang et al., 2023c; Tang et al., 2023a）或检索蒸馏（Izacard et al., 2021）的研究，可能有助于语言智能体学习更好的检索过程。
- **更新学习或决策过程。** 理论上，CoALA 智能体可以学习用于学习或决策的新过程，从而获得可观的自适应性。不过总体而言，对这些过程的更新对智能体的功能性与对齐（alignment）都有风险。目前我们尚不清楚有任何语言智能体实现了这种形式的学习；第 6 节将进一步讨论这种可能性。

RL 智能体通常固定一种学习方式（如 Q-learning、PPO 或 A3C），通过更新模型参数来学习；而语言智能体可以从多样的学习过程中选择。这使它们能够通过存储任务相关的语言来快速学习（比参数更新更便宜、更迅捷），并利用多种学习形式来复合式地自我改进（例如第 5 节讨论的 Generative Agents）。

最后，尽管我们的讨论主要聚焦于"向记忆中添加"，**修改与删除**（"遗忘"或 unlearning 的情形）在近期语言智能体中研究不足。我们将在第 6 节进一步讨论这些方面。

### 4.6 决策

在动作空间中有了各类动作（接地、学习、推理、检索）之后，语言智能体应如何选择执行哪个动作？这由**决策过程**处理，它实际上是顶层的、或者说 "main" 的智能体程序。CoALA 把这个顶层程序结构化为**决策周期**（图 4B），每个周期产出一个外部接地动作（4.2 节）或一个内部学习动作（4.5 节）。在每个周期中，程序代码定义一串推理与检索动作来提议、评估备选方案（**规划阶段**），然后执行所选动作（**执行阶段**），随后循环再次开始。

**规划阶段。** 在规划期间，推理与检索可以被灵活地用于提议、评估和选择动作；这些子阶段可以交替或迭代，以在采取外部动作之前构建多步模拟（Tamari et al., 2020; Yao et al., 2023; Hao et al., 2023）。它还使智能体能够迭代改进候选解——例如用 LLM 模拟候选解、识别缺陷，并提出修复这些缺陷的修改（Kirk et al., 2023; Shinn et al., 2023）。

- **提议（Proposal）。** 该子阶段生成一个或多个候选动作。通常做法是用推理（可选地加上检索）从 LLM 中采样一个（Huang et al., 2022c）或更多（Chen et al., 2021; Wang et al., 2022b）外部接地动作。对于动作数量有限的简单领域，提议阶段可能直接包含所有动作（例如第 5 节的 SayCan）。更精巧的智能体使用 if-else 或 while-if 的代码结构（Wang et al., 2023a; Park et al., 2023）；而部署在良定义领域中的智能体可能利用结构化模拟器（Haslum et al., 2019）生成看似合理的推演（rollout）（Liu et al., 2023a; Dagan et al., 2023）。
- **评估（Evaluation）。** 若提议了多个动作，评估子阶段为每个动作赋予一个值。这可以使用启发式规则、LLM（困惑度）值（Ahn et al., 2022）、学习得到的状态价值（Yao et al., 2020）、LLM 推理（Yao et al., 2023; Hao et al., 2023），或它们的某种组合。特别地，LLM 推理可以通过在内部模拟动作从外部世界获得的接地反馈来帮助评估动作（Hao et al., 2023; Yang et al., 2023）。
- **选择（Selection）。** 给定一组动作及其值，选择步骤要么选出其中一个执行，要么全部否决并回到提议步骤。依据动作值的形式，选择可采用 argmax、softmax，或多数投票（Wang et al., 2022b）等替代方案。

**执行（Execution）。** 所选动作通过执行智能体源代码中的相关过程来实施。依智能体实现而定，这可能是一个外部接地动作（如 API 调用；4.2 节），也可能是一个内部学习动作（如写入情景记忆；4.5 节）。可以从环境获得一次观测，作为智能体动作的反馈，然后循环再次开始。

从实证上看，许多早期语言智能体只是用 LLM 提议一个动作（Schick et al., 2023）、一串动作（Huang et al., 2022b），或在一组固定动作上做评估（Ahn et al., 2022），中间没有推理或检索。后续工作（Yao et al., 2022b; Shinn et al., 2023; Xu et al., 2023b; Lin et al., 2023; Wang et al., 2023a; Park et al., 2023）则利用中间推理与检索来分析处境、制定并维护行动计划、根据环境反馈改进上一步动作，并用更复杂的过程来提议单个动作。最近，研究开始探索更复杂的决策：通过迭代的提议与评估来考虑多个动作。这些过程仿照经典规划算法：例如 Tree of Thoughts（Yao et al., 2023）与 RAP（Hao et al., 2023）分别用 LLM 实现 BFS/DFS 与蒙特卡洛树搜索（Browne et al., 2012，MCTS）。LLM 被用来生成提议（即以某个动作为条件模拟推演）并对其评估（即给所提议动作的结果估值）。

## 5 案例研究

通过对记忆模块、动作空间与决策过程做变体与消融，CoALA 可以表达广泛谱系的语言智能体。表 2 列出了不同领域中一些流行的近期方法——从 Minecraft 到机器人，从纯推理到社会仿真。CoALA 帮助我们刻画它们的内部机制，并以简单而结构化的方式揭示它们的异同。

**SayCan**（Ahn et al., 2022）把语言模型接地到厨房中的机器人交互上，以满足用户指令（例如"我刚健身完，你能给我拿点喝的和小吃补充一下吗？"）。它的长期记忆只有程序性记忆（一个 LLM 和一个学到的价值函数）；动作空间只有外部动作——一组固定的 551 个接地技能（如"找到苹果""去桌子那边"），没有推理、检索或学习等内部动作。在决策时，SayCan 用 LLM 与学到的价值函数组合来评估每个动作，平衡技能的"有用性"（usefulness）与"可接地性"（groundedness）。因此，SayCan 把 LLM（与学到的价值函数结合）当作**单步规划器**使用。

**表 2：把一些近期语言智能体投射到 CoALA 框架中。**

| 智能体 | 长期记忆¹ | 接地（外部） | 内部动作 | 决策 |
| --- | --- | --- | --- | --- |
| SayCan（Ahn et al., 2022） | — | 物理 | — | 评估（evaluate） |
| ReAct（Yao et al., 2022b） | — | 数字 | 推理 | 提议（propose） |
| Voyager（Wang et al., 2023a） | 程序性 | 数字 | 推理/检索/学习 | 提议 |
| Generative Agents（Park et al., 2023） | 情景/语义 | 数字/智能体 | 推理/检索/学习 | 提议 |
| Tree of Thoughts（Yao et al., 2023） | — | 数字² | 推理 | 提议、评估、选择 |

> ¹ 所有智能体都含有某种程序性记忆（智能体代码与 LLM 权重），因此此处只列出**可写**的程序性记忆。
> ² 一种特殊的数字接地：唯一的外部动作是提交最终答案。

**ReAct**（Yao et al., 2022b）是接地到多种数字环境（如维基百科 API、文本游戏、网站）的语言智能体。与 SayCan 一样，它缺少语义记忆或情景记忆，因此没有检索或学习动作。其动作空间由（内部）推理与（外部）接地构成。它的决策周期固定为：先用一个推理动作分析处境并（重新）制定行动计划，然后生成一个接地动作，没有评估与选择阶段。ReAct 可视为**同时利用内部与外部动作的最简语言智能体**，也是最早展示二者协同效应的工作：推理帮助指导行动，而行动提供环境反馈以支撑推理。

**Voyager**（Wang et al., 2023a）是接地到 Minecraft API 的语言智能体。与通过学到的价值函数接地到感知的 SayCan 不同，Voyager 的接地是纯文本的。它有一个长期程序性记忆，存放一个基于代码的接地过程库，即"技能"（如 "combatZombie"、"craftStoneSword"）。这个库是层次化的：复杂技能可以把更简单的技能作为子过程调用（例如当背包里没有剑时，"combatZombie" 可以调用 "craftStoneSword"）。最引人注目的是，它的动作空间包含全部四类动作：接地、推理、检索与学习（通过新增接地过程）。在一个决策周期中，Voyager 首先推理：若工作记忆中缺少任务目标，就提议一个新的任务目标；然后推理：提议一个基于代码的接地过程来求解该任务。在下一个决策周期，Voyager 对环境反馈做推理以判断任务是否完成；若成功，就选择一个学习动作，把该接地过程加入程序性记忆；否则用推理改进代码并重新执行。长期记忆与程序性学习的重要性通过与 ReAct、AutoGPT 等基线以及去掉程序性记忆的消融对比得到了实证验证。结果显示 Voyager 能更好地探索区域、掌握科技树，并零样本泛化到未见过的任务。

**Generative Agents**（Park et al., 2023）是接地到一个沙盒游戏的语言智能体，可与环境及其他智能体交互。其动作空间同样包含全部四类动作：接地、推理、检索与学习。每个智能体有一个长期情景记忆，以列表形式存储事件。这些智能体用检索与推理对情景记忆生成"反思"（如"我现在喜欢滑雪了"），再写入长期语义记忆。决策时，它从语义记忆中检索相关反思，然后推理制定一天的高层计划。执行计划过程中，智能体会收到一串接地观测，并对其推理以维持或调整计划。

**Tree of Thoughts（ToT）**（Yao et al., 2023）可视为一类特殊的语言智能体：它只有一个外部动作，即向推理问题（24 点游戏、创造性写作、填字游戏）提交最终解。它没有长期记忆，内部动作空间只有推理；但它与此前所有智能体的不同在于其**深思熟虑的决策**。在规划时，ToT 依据 LLM 推理迭代地提议、评估并选择"思维"（即推理动作），并用树搜索算法维护它们，从而实现全局探索以及局部的回溯与前瞻。

## 6 可操作洞见

与近期一些围绕语言智能体的实证综述（Mialon et al., 2023; Weng, 2023; Wang et al., 2023b）相比，CoALA 提供了一个扎根于成熟认知架构研究的理论框架。由此得到一组独特且有互补价值的可操作洞见。

**模块化智能体：不要只想着单体（monolith）。** 也许我们最重要的建议是：智能体应当结构化、模块化。在实践上，正如机器人平台之间共用标准化软件（Quigley, 2009; Macenski et al., 2022），一个面向语言智能体的框架可以整合技术投入并提升兼容性。

- 在学术研究中，标准化术语使跨工作的概念比较成为可能（表 2），而开源实现将进一步促进模块化的即插即用与复用。例如，马尔可夫决策过程（Puterman, 2014）的理论框架为强化学习提供了一套标准化的概念与术语（状态、动作、奖励、转移），相应地，OpenAI Gym（Brockman et al., 2016）这样的实证框架提供了标准化抽象（`obs, reward, done, info = env.step(action)`），极大便利了 RL 的实证工作。因此，为语言智能体实现有用的抽象（如 `Memory`、`Action`、`Agent` 类），并把更简单的智能体作为示例投射到这样一个实证版 CoALA 框架中，将是及时且有影响力的工作。
- 在产业应用中，维护一个全公司统一的"语言智能体库"可以通过促进跨单个智能体部署的测试与组件复用来减少技术债（Sculley et al., 2014; Lwakatare et al., 2020）。它还能统一客户体验：终端用户面对的不再是各团队各搞一套的大杂烩，而是同一个基础智能体在特定情境下的实例化。
- **智能体设计中 LLM 与代码的分工。** CoALA 智能体拥有两种形式的程序性记忆：智能体代码（确定性规则）与 LLM 参数（一个庞大、随机的产生式系统）。智能体代码可解释、可扩展，但在随机性面前往往脆弱，且只能处理设计者预想到的情形；相反，LLM 参数难以解释，但在新情境下具有很强的零样本灵活性（Huang et al., 2022b）。因此 CoALA 建议：克制地使用代码，只用代码实现那些能弥补 LLM 局限的通用算法——例如用树搜索缓解自回归生成带来的短视（Yao et al., 2023; Hao et al., 2023）。

**智能体设计：不要只想着"推理"。** CoALA 在三个不同概念上定义智能体：（i）内部记忆；（ii）一组可能的内部与外部动作；（iii）在这些动作之上的决策过程。用 CoALA 开发一个应用专用智能体，就是依次为这三个组件指定实现。我们假定智能体的环境与外部动作空间已给定，并说明如何用 CoALA 确定合适的高层架构。例如，设想设计一个个性化零售助手（Yao et al., 2022a），根据用户的查询与购买历史帮其找到相关商品。此时外部动作将是对话或向用户返回搜索结果。

- **确定需要哪些记忆模块。** 在零售助手例子中，智能体最好拥有包含在售商品集合的语义记忆，以及关于每位顾客过往购买与交互的情景记忆；还需要定义查询这些数据存储的函数的程序性记忆，以及追踪对话状态的工作记忆。
- **定义智能体的内部动作空间。** 这主要是定义对每个记忆模块的读、写访问权限。在例子中，智能体应对情景记忆有读写权限（以便存储与顾客的新交互），而对语义记忆与程序性记忆只有只读权限（因为它不应更新库存或自己的代码）。
- **定义决策过程。** 这一步规定如何执行推理与检索动作，以选择一个外部动作或学习动作。一般来说，这需要在性能与泛化之间权衡：更复杂的过程能更好地贴合特定问题（如 Voyager 之于 Minecraft），而更简单的过程更与领域无关、更易泛化（如 ReAct）。对零售助手，我们可能希望鼓励检索与该用户交互的情景记忆，以形成其搜索意图的先验；并加入显式的评估步骤，推理某组搜索结果是否满足该意图。我们还可以把学习推迟到交互结束时（Shinn et al., 2023; Park et al., 2023），先把整段情节做摘要再存入情景记忆，从而简化决策过程。

**结构化推理：不要只想着提示工程。** 早期提示工程通过底层的字符串操作来操纵 LLM 的输入与输出。CoALA 建议采用更结构化的推理过程来更新工作记忆中的变量。

- 诸如 LangChain（2022）与 LlamaIndex（2023）之类的提示框架可用来定义更高层的推理步骤序列，减轻每次 LLM 调用的推理负担与底层提示雕琢的工作量。Guidance（2023）与 OpenAI function calling（OpenAI, 2023b）之类的结构化输出解析方案可以帮助更新工作记忆变量。定义并构建良好的工作记忆模块也将是未来研究的重要方向；这类模块对于需要把 LLM 推理与大规模代码基础设施无缝集成的产业方案尤为重要。
- 智能体中的推理用例可以反过来影响并重塑 LLM 的训练，包括训练实例的**类型**（如用于自评估、反思、动作生成的推理）与**格式**（如 CoT（Wei et al., 2022b）、ReAct（Yao et al., 2022b）、Reflexion（Shinn et al., 2023））。现有 LLM 默认是针对 NLP 任务训练与优化的，但智能体应用已经探索出新的 LLM 推理模式（如自评估）并被证明广泛有用。朝这些能力训练或微调过的 LLM，更有可能成为未来智能体的骨干。

**长期记忆：不要只想着检索增强。** 传统检索增强语言模型（Guu et al., 2020; Lewis et al., 2020; Borgeaud et al., 2022）只从人类书写的语料中读取，而记忆增强的语言智能体可以自主读写自己生成的内容。这为高效的终身学习开启了大量可能性。

- 把已有的人类知识与新的经验、技能结合起来，可以帮助智能体高效地"启动"学习。例如，一个写代码的智能体可以被赋予以手册或教科书形式存在的语义编程知识；随后它可以从经验中生成自己的情景知识，对这些经验做反思以生成新的语义知识，并逐步以代码库的形式创建程序性知识（存放有用的方法）。
- 把检索与推理结合起来，有助于更好地为规划提供依据。近期的计算心理学模型提示记忆召回与决策是一个整合的过程（Zhou et al., 2023a; Zhao et al., 2022）——这暗示，让记忆搜索与前向模拟交替进行的自适应机制，将使智能体最大限度地运用其知识。

**学习：不要只想着上下文内学习（in-context learning）或微调。** CoALA 对"学习"的定义涵盖了这些方法，但进一步扩展到存储新经验或新知识，或写入新的智能体代码（4.5 节）。重要的未来方向包括：

- **通过修改智能体代码进行元学习**将使智能体学得更有效。例如，学习更好的检索过程可以让智能体更好地利用自身经验。近期的查询扩展类技术（Nogueira et al., 2019; Wang et al., 2023c; Tang et al., 2023a）可以让智能体推理"哪些知识何时会有用"，并把它作为元数据存储以方便日后召回。这类元学习将使智能体超越人类书写的代码，但因难度与风险而研究不足。
- **新的学习（与遗忘）形式**可以包括：为特定推理子任务微调更小的模型（Zelikman et al., 2022; Huang et al., 2022a; Ahn et al., 2022）、删除不需要的记忆条目以实现"遗忘"（Nguyen et al., 2022c），以及研究多种学习形式之间的交互效应（Tuyls et al., 2022; Park et al., 2023; Xie et al., 2023; Khattab et al., 2022）。

**动作空间：不要只想着外部工具或动作。** 尽管"动作空间"是强化学习中的标准术语，它在语言智能体语境中却用得很少。CoALA 主张定义一个清晰且适合任务的动作空间，同时包含内部动作（推理、检索、学习）与外部动作（接地），这将有助于把智能体设计系统化并提供指引。

- **动作空间的规模。** 能力更强的智能体（如 Voyager、Generative Agents）拥有更大的动作空间，这也意味着它们面对更复杂的决策问题。因此，这些智能体依赖更定制化或手工设计的决策过程。动作空间与决策复杂度之间的权衡，是开发智能体之前就应考量的基本问题；只取解决给定任务所必需的最小动作空间，可能是更好的选择。
- **动作空间的安全性。** 动作空间的某些部分天然更具风险。"学习"动作（尤其是程序性的删除与修改）可能造成**内部**伤害；而"接地"动作（如 bash 终端里的 `rm`、人机对话中的有害言论、物理环境中持刀）可能造成**外部**伤害。目前的安全措施通常是任务特定的启发式：例如在 Python 中移除 `os` 相关操作（Chen et al., 2021）、在对话中过滤关键词（Chowdhery et al., 2022; Driess et al., 2023）、把机器人限制在受控环境中（Ahn et al., 2022）。然而，随着智能体接地到更复杂的环境、内部机制更丰富，可能有必要显式规定并对动作空间做消融，以预测和防范最坏情形（Yao and Narasimhan, 2023）。

**决策：不要只想着生成动作。** 我们认为语言智能体最令人兴奋的未来方向之一是决策：如 4.6 节所述，大多数工作仍局限于提议（或直接生成）单个动作；现有智能体才刚刚触及更审慎的"提议—评估—选择"式决策过程的皮毛。

- **把基于语言的推理与基于代码的规划混合起来，可能兼得两者之长。** 现有方法要么直接用自然语言规划（Huang et al., 2022c; Ahn et al., 2022），要么用 LLM 把自然语言翻译成结构化的世界模型（Wong et al., 2023; Liu et al., 2023a; Zhang et al., 2023a; Li et al., 2023a; Guan et al., 2023; Silver et al., 2022, 2023）。未来工作可以把二者整合：正如 Soar 内嵌了一个用于物理推理的模拟器（Laird, 2022），智能体也可以即时编写并执行模拟代码，以评估计划的后果。更多讨论见第 7 节。
- **把审慎推理扩展到真实世界场景。** 已有工作实现了经典规划与树搜索（Yao et al., 2023; Hao et al., 2023; Liu et al., 2023a; Dagan et al., 2023），但使用的是 24 点游戏、积木搭建这类玩具任务。把这些方案扩展到带接地（Qin et al., 2023）与长期记忆的更复杂任务，是一个令人兴奋的方向。
- **用元推理（metareasoning）提升效率。** LLM 调用既慢又计算密集。用 LLM 做决策需要在计算代价与所得改进方案的效用之间权衡。多数 LLM 推理方法通过指定推理深度（Yao et al., 2023）来固定搜索预算，但人类似乎会自适应地分配计算资源（Russek et al., 2022; Lieder and Griffiths, 2020; Callaway et al., 2022; Gershman et al., 2015）。未来工作应发展估计规划效用的机制（Laidlaw et al., 2023）并据此调整决策过程：可以通过摊销（amortization，例如依据以往动作的结果微调 LLM；Nguyen, 2023; Hamrick et al., 2019）、在多个决策子过程之间路由（例如 ReAct 研究了回退到 CoT 以及反向回退；Yao et al., 2022b; Wei et al., 2022b），或更新决策过程本身。
- **校准与对齐。** 更复杂的决策目前受限于若干问题：过度自信与校准不良（Jiang et al., 2021; Braverman et al., 2020; Chen et al., 2022）、与人类价值不一致或存在偏见（Liang et al., 2021; Feng et al., 2023）、自评估中的幻觉（Shinn et al., 2023），以及面对不确定性时缺乏人在回路（human-in-the-loop）机制（Nguyen et al., 2022a; Ren et al., 2023）。解决这些问题将显著提升 LLM 作为智能体骨干的效用。

## 7 讨论

除上述实践洞见外，CoALA 还提出了一些开放的概念性问题。我们简要指出其中最有趣者，作为未来研究与讨论的重要方向。

**LLM 还是 VLM：推理应当只用语言，还是多模态？** 多数语言智能体用纯语言模型做决策（Yao et al., 2022b; Wang et al., 2023a; Yao et al., 2023），在必要时用单独的描述生成模型把环境观测转换为文本（Ahn et al., 2022; Zeng et al., 2022）。然而最新一代语言模型是多模态的，允许图像与文本交错输入（OpenAI, 2023a; Alayrac et al., 2022; Team et al., 2023; Li et al., 2023b）。构建在这类多模态模型上的语言智能体可以原生地对图像与文本输入推理（Bavishi et al., 2023; Elsen et al., 2023; Liu et al., 2023b; Hong et al., 2023b; Driess et al., 2023），从而能够直接摄取感知数据并产出动作。这绕过了有损的图像转文本转换；但同时，它也把推理与规划过程紧密耦合到模型的输入模态上。

在高层次上，两种方法可视为把非语言模态转换到核心推理模型的语言域上的不同**分词方案**：模块化方法用单独的图像转文本模型把感知数据转为语言（Ahn et al., 2022; Zeng et al., 2022），而一体化方法把图像直接投影到语言模型的表示空间（Bavishi et al., 2023; Elsen et al., 2023; Liu et al., 2023b）。一体化的多模态推理可能带来更接近人类的行为：基于 VLM 的智能体可以"看见"网页，而基于 LLM 的智能体更可能是直接拿到原始 HTML。不过，把智能体的感知与推理系统耦合起来，会让智能体更偏向特定领域，也更难更新。无论哪种情形，CoALA 描述的基本架构原则——内部记忆、结构化动作空间、泛化的决策——都可用于指导智能体设计。

**内部还是外部：智能体与其环境的边界在哪里？** 人类或机器人显然与具身环境相区分，而数字语言智能体的边界则不那么清楚。例如，维基百科数据库是内部语义记忆，还是外部数字环境（Yao et al., 2022b）？如果智能体在提交答案前迭代执行并改进代码（Shinn et al., 2023; Yang et al., 2023），代码执行是内部还是外部？如果一个方法由"提议提示"与"评估提示"构成（Yao et al., 2023），应视为单个智能体，还是两个协作的更简单智能体（提议者与评估者）？

我们认为，边界问题可以依据**可控性**（controllability）与**耦合性**（coupling）来回答。例如，维基百科是不可控的：它是一个可能被其他用户意外修改的外部环境；而只有一个智能体可以写入的离线版本是可控的，因此可视为内部记忆。类似地，在内部虚拟环境上执行代码应视为内部推理动作，而在外部机器上执行代码（可能带有安全漏洞）应视为外部接地动作。最后，如果智能体的某些方面——如提议提示与评估提示——是为彼此设计且相互依赖的，那么它们紧耦合，最好概念化为单个智能体内部的组件；相反，若这些步骤各自独立有用，多智能体视角可能更合适。虽然这些两难主要是概念性的，但这种理解可以支撑智能体设计，并帮助领域在共享术语上达成一致。实践者也可以只选择自己偏好的划分方式，只要它自洽且对自身工作有用。

**物理还是数字：哪些差异值得关注？** 动物在物理世界中只能活一次，而数字环境（如互联网）往往允许串行（通过重置）与并行的多次尝试。这意味着数字智能体可以更大胆地探索（例如打开一百万个网页），也可以自我克隆以并行求解任务（例如一百万个网页智能体尝试不同的网页路径），这可能催生出不同于当前那些受人类认知启发的决策过程（Griffiths, 2020）。

**学习还是行动：智能体应如何持续、自主地学习？** 在 CoALA 框架中，学习与接地一样是决策周期的结果动作：智能体有意地选择把信息提交到长期记忆。这与多数智能体形成对比——它们只是固定一个学习计划，决策仅用于外部动作。然而生物智能体没有这种奢侈：它们必须在生命周期内平衡学习与外部行动，选择何时学、学什么（Mattar and Daw, 2018）。更灵活的语言智能体（Wang et al., 2023a; Park et al., 2023）会采用类似设计，把学习与外部动作同等对待。学习可以在常规决策中被提议为一个可能的动作，使智能体能够把它"推迟"到合适的时机。

**GPT-4 还是 GPT-N：更强的 LLM 会如何改变智能体设计？** 随着规模带来新的 LLM 能力（Wei et al., 2022a），智能体设计是一个移动的目标。例如，GPT-2（Radford et al., 2019）这样的早期语言模型无法支撑 LLM 智能体——当时的工作需要把 GPT-2 与强化学习结合来做动作生成（Yao et al., 2020）；GPT-3（Brown et al., 2020）解锁了 NLP 任务上灵活的少样本与零样本推理；而只有 GPT-4（OpenAI, 2023a）才开始提供更可靠的自评估（Saunders et al., 2022; Shinn et al., 2023; Yao et al., 2023）与自我精炼（Madaan et al., 2023; Chen et al., 2023b）。未来的 LLM 会进一步减少对手写规则与额外学习模型的依赖吗？这会要求改变 CoALA 框架吗？

作为一个思想实验，想象 GPT-N 能在上下文中"模拟"记忆、接地、学习与决策：列出所有可能的动作，逐个模拟并评估，并把全部长期记忆显式地维护在一个极长的上下文中。或者更激进地说：也许 GPT-N+1 能通过在神经元中隐式地模拟这些过程来直接生成下一个动作，而无需上下文中的任何中间推理。虽然这些极端情形在近期不太可能出现，但渐进的改进仍可能改变 CoALA 各组件的重要性。例如，更长的上下文窗口可能降低长期记忆的重要性；而用于内部评估与模拟的更强推理能力，可能支持更长视野的规划。总体而言，LLM 不受生物学的限制（Griffiths, 2020），其涌现特性一直难以预测。尽管如此，CoALA——以及更广义的认知科学——仍可能有助于梳理语言智能体在哪些任务上成功或失败，并提示用哪些基于代码的过程来补足给定 LLM 在给定任务上的不足。即使在最极端的情形下——GPT 在神经元中实现了 CoALA 的全部机制——把 CoALA 用作发现并解释那些隐式回路的概念性指南，仍可能是有益的。当然，如第 6 节所述，智能体的应用用例也会帮助发现、定义并塑造 LLM 的能力。正如芯片与计算机架构协同演化，语言模型与智能体的设计也应形成一条相互促进的道路。

---

## 8 结论

我们提出了**语言智能体的认知架构（CoALA）**，一个用于描述与构建语言智能体的概念框架。该框架从符号人工智能与认知科学的深厚历史中汲取灵感，把数十年前的洞见与 LLM 的前沿研究连接起来。我们相信，这一取向为发展更通用、更像人类的人工智能提供了一条路径。

| 产生式系统（production system） | 由"前置条件 → 动作"规则组成的计算形式化；反复应用规则来生成/改写字符串 |
| 字符串改写（string rewriting） | 用规则把形如 $XYZ$ 的串改写为 $XWZ$，是形式语言与 Chomsky 语法的基础 |
| 认知架构（cognitive architecture） | 模仿人类认知、显式实例化感知/记忆/规划等过程的系统蓝图（Soar、ACT-R 等） |
| 工作记忆（working memory） | 当前决策周期内"随手可取"的信息：感知输入、活跃目标、中间推理结果 |
| 情景记忆（episodic memory） | 过往决策周期/回合的经验轨迹，可供后续检索作为示例 |
| 语义记忆（semantic memory） | 关于世界与自身的知识、事实、反思结论 |
| 程序性记忆（procedural memory） | "怎么做"的知识：LLM 权重（隐性）+ 智能体代码/技能库（显性） |
| 接地（grounding） | 与外部环境交互的动作：物理（机器人）、对话（人/其他智能体）、数字（API/网站/代码执行） |
| 检索（retrieval） | 长期记忆 → 工作记忆的读取动作，可用规则、稀疏（BM25）或稠密检索实现 |
| 推理（reasoning） | 对工作记忆的读写：总结、提炼、反思、模拟，是 CoALA 相对传统认知架构新增的动作类型 |
| 学习（learning） | 写入长期记忆：存经验、存知识、微调参数、改代码（含改提示、加技能、改检索） |
| 决策周期（decision cycle） | "规划（提议→评估→选择）→ 执行 → 观测"的循环，相当于程序的 main 循环 |
| 提议/评估/选择（propose/evaluate/select） | 规划的三个子阶段；ToT、RAP 分别在上面实现了树搜索与 MCTS |
| 元推理（metareasoning） | 对"想多少"本身做决策：估计规划的效用并动态分配计算预算 |
| 遗忘（unlearning） | 修改或删除长期记忆条目，本文指出这是被严重低估的方向 |

**核心数字速记**

- 论文体量：正文 19 页、5 幅图、2 张表；arXiv 2309.02427v3（2024-03-15，TMLR camera-ready），CC BY 4.0。
- CoALA 的三维分解：**记忆**（工作 + 情景/语义/程序性长期）、**动作**（内部：检索/推理/学习；外部：接地）、**决策**（规划 + 执行）。
- 动作空间四分类：接地、检索、推理、学习（表 2 用它给 SayCan / ReAct / Voyager / Generative Agents / ToT 做统一刻画）。
- 案例对比的关键差异：SayCan 有 551 个固定接地技能、只有"评估"式单步规划；ReAct 只有"推理 + 接地"、固定"提议"；Voyager 有四类动作与可增长的程序性技能库；ToT 只有推理动作但拥有完整的"提议—评估—选择"。
- 与 RL 的类比落点：CoALA ≈ 语言智能体版的 MDP + Gym（`Memory` / `Action` / `Agent` 抽象）。
